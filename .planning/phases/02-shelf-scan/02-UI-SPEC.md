# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: `--auto`. No user questions were asked. Values come from 02-CONTEXT.md (D-03, D-07..D-17), 02-RESEARCH.md (Patterns 1, 6, 7, 8), the approved 01-UI-SPEC.md and the shipped code in `src/`. Values not covered upstream are researcher defaults marked `[default]`.

**Surfaces in scope:** the `/upload` page (dropzone, upload tip, photo status list), the `/spines` page (filter bar, sticky photo section headers, spine cards with inline-editable fields), the Re-scan confirm dialog, the orphaned-spine Re-attach dialog and Dismiss confirm, and the loading and error states of both pages.
**Out of scope:** Discogs candidates (Phase 3 fills the card footer slot), status filters and counts beyond "Needs review" (REV-03, Phase 4), bounding-box overlay, manual boxes, keyboard review and bulk actions (v2 SPEED-*).
**Unchanged from Phase 1:** the app shell (sticky 56px header, Upload / Spines / Settings nav, status indicator), the theme (follows the OS), the fonts, every color token, the focus ring, and the toast placement. This spec only adds to them.

## Spacing Scale

Same scale as Phase 1. Declared values (multiples of 4):

| Token | Value | Tailwind | Phase 2 usage |
|-------|-------|----------|---------------|
| xs | 4px | `1` | Icon-to-text gap in badges and buttons, label-row item gap, gap between field label row and its input |
| sm | 8px | `2` | Gap between badges in a header, gap between buttons, thumbnail-to-text gap in section headers, toggle-group-to-select gap |
| md | 16px | `4` | Spine card padding (`p-4`) and its internal gaps, field grid gap (`gap-4`), gap between spine cards, upload row horizontal padding (`px-4`) |
| lg | 24px | `6` | Dropzone padding (`p-6`), gap between the dropzone, the tip and the Photos card, gap between photo sections' last card and the next header |
| xl | 32px | `8` | Page title block to first content block (same as Phase 1), `<main>` top padding |
| 2xl | 48px | `12` | Empty-state vertical padding |
| 3xl | 64px | `16` | Empty-state top offset |

Layout constants:
- `/upload` content column is `max-w-3xl` (768px), left-aligned in the shell container. `/spines` uses the full shell width (`max-w-6xl`, 1152px).
- Dropzone minimum height is 192px (`min-h-48`).
- Upload row thumbnail is 48x48 (`size-12`); section header thumbnail is 40x40 (`size-10`). Both `rounded-md object-cover bg-muted`. The server generates `thumbs/` at 160px on the long edge (WebP), enough for 2x displays at 48px and up to 80px. `[default]`
- Spine crop: rendered `w-full h-auto`, `max-h-32` (128px), `object-contain object-center` on a `bg-muted rounded-md` well with `min-h-12` (48px). The `<img>` carries the crop's real `width`/`height` attributes so lazy loading never shifts layout.
- Photo section header is sticky at `top-14` (directly under the 56px app header), `z-30`, `bg-background/95 backdrop-blur supports-[backdrop-filter]:bg-background/80`, `border-b`, `py-3`, with 16px (`mt-4`) between the header and its first card.
- Field grid: 6 columns at `lg` (≥1024px): Artist span 3, Title span 3, Format span 2, Label span 2, Catalog number span 2, Raw text span 6. 2 columns at `sm` (Raw text spans 2). 1 column below 640px.

Exceptions:
- All Phase 1 exceptions still apply (1px borders, 2px nav underline, 8px status dot, `px-3` for nav, status indicator and value wells, 36px targets on a desktop-only tool, 360px minimum viewport).
- `py-3` (12px) vertical padding is allowed for Upload rows and photo section headers.
- The per-field revert button is 24x24 (`size-6`, icon `size-3.5` = 14px) because it sits in a 16px-tall label row. It is never the only way to act (Escape and retyping also work) and has a tooltip and `aria-label`.
- The dropzone uses a 2px dashed border (`border-2 border-dashed`) so the drop target reads as a target.

**Accent reserved for** (exhaustive for Phase 2; Phase 1's list still applies to the shell and Settings):
1. The "Choose photos" button inside the dropzone.
2. The dropzone's dashed border and its `ImageUp` icon while a valid drag is over it (`isDragAccept`): `border-primary`, `bg-primary/5`, icon `text-primary`.
3. The "Upload photos" action in the `/spines` no-data empty state.
4. The confirm button of the Re-scan dialog ("Re-scan photo") and of the Re-attach dialog ("Re-attach spine").
5. The selected option's ring in the Re-attach dialog (`ring-2 ring-primary`, RadioGroup indicator).
6. "Open Settings" in the Claude-CLI-not-ready Alert on `/upload` (the dropzone is disabled in that state, so it is the only primary action).
7. Focus rings (`--ring`) everywhere (Phase 1 rule).

Accent is NOT used for status badges, the filter toggle's pressed state (it uses the toggle default `bg-accent` = muted), "View spines", the Re-scan trigger, the crop, or field borders.

**Warning (`--warning`) reserved for** (exhaustive):
1. The border of a spine field whose AI value is non-empty, unedited and below the confidence threshold (`border-warning`, plus `focus-visible:ring-warning/40`).
2. The `TriangleAlert` icon (16px) in that field's label row, which is the tooltip trigger for its score.
3. The `TriangleAlert` icon in the card's worst-field badge.
4. The `TriangleAlert` icon in the photo-level "Retake closer" (D-03) and "May be incomplete" badges.
5. The `TriangleAlert` icon in the "No longer detected" badge on orphaned spines, plus a 1px `border-warning/60` on the orphaned card.
6. The `Sparkles` icon before the "Latest scan reads …" hint under an edited field (D-15).

Warning is **never used for text**. `#d97706` on `#ffffff` is about 3.2:1, below AA for 12-14px text, so it is limited to borders and icons (non-text contrast, 3:1 minimum, passes). Badge text next to a warning icon stays `text-foreground`.

**Destructive reserved for** (Phase 2): the "Error" status badge's `CircleX` icon and label, scan and upload error reason text, the dropzone border and message while an invalid drag is over it (`isDragReject`), inline field save errors (`FieldError`, plus `aria-invalid` border), the "Dismiss spine" ghost trigger text, and the Dismiss confirm button.

Contrast: every text pair meets WCAG AA (4.5:1). Accent `#4f46e5` on `#ffffff` is about 6.3:1.

## Layout & Interaction Contract

### Focal points (one per surface)
- **`/upload`:** the dropzone. It is the largest element (full column width, min 192px tall) and holds the page's only accent button, "Choose photos". The page title and the Photos list are secondary. When the Claude CLI isn't ready, the focal point moves to the Alert and its "Open Settings" button, and the dropzone is dimmed.
- **`/spines` (page):** the stack of spine cards. The title and filter bar stay quiet (no accent), and section headers are thin sticky strips.
- **Each spine card:** the horizontal crop. It spans the full card width at the top, sits on the muted well, and comes before the fields, so the eye lands on the spine first and then compares the fields below it (core value: crop always beside the AI read). Within the fields, the low-confidence warning borders are the only secondary emphasis.
- **Dialogs:** the confirm button (accent, or destructive for Dismiss) is the single emphasized control. The dismiss button is ghost.

### Shared: data loading and polling
- `src/app/providers.tsx` (`'use client'`) wraps the app in `QueryClientProvider` and nuqs's `NuqsAdapter` (`nuqs/adapters/next/app`), inside the existing `ThemeProvider` / `TooltipProvider`.
- `useQuery(['photos'])` → `GET /api/photos`. `useQuery(['spines', {photo, review}])` → `GET /api/spines`.
- Both use `refetchInterval` as a function: **1500ms while any photo is `queued`, `preparing`, `calling` or `parsing`; 3000ms (`POLL_RETRY_MS`) while the last poll failed, so the "Couldn't refresh" alert clears on the next successful poll; otherwise `false`** (02-RESEARCH Pattern 7) (corrected by G-02-3). `refetchOnWindowFocus: true`. After an upload or re-scan request succeeds, invalidate both queries and dispatch the existing `app:status-refresh` window event so the header indicator updates at once.
- UI status mapping from `vision_runs.status` (one place, `PhotoStatusBadge`):

| Run status | Badge (all `variant="outline"`) | Sub-line (Caption, muted) |
|-----------|-------------------------------|---------------------------|
| client: waiting | `Clock` icon (muted), "Waiting" | `Waiting to upload` |
| client: uploading | `Spinner`, "Uploading" | `Uploading…` |
| `queued` | `Clock` icon (muted), "Queued" | `Waiting for the worker` |
| `preparing` | `Spinner`, "Analyzing" | `Preparing image…` |
| `calling` | `Spinner`, "Analyzing" | `Claude is reading the spines… {m:ss}` (elapsed since `spawned_at`, mono, ticks every second client-side) |
| `parsing` | `Spinner`, "Analyzing" | `Cropping spines…` |
| `done` | `CircleCheck` (`text-success`), "Done" | `{n} spines · {model label}` (e.g. `38 spines · Claude Opus 5.5`); `1 spine` singular; `No CDs found` at 0 |
| `error` | `CircleX` (`text-destructive`), "Error", label `text-destructive` | The error reason (Body, `text-destructive`, wraps, max 3 lines then `line-clamp-3` with the full text in a `title` attribute) |

### `/upload`
Order, top to bottom, in a `max-w-3xl` column:

1. **Title block:** Display "Upload", then a Body muted description (copy below), 8px gap. 32px to the next block.
2. **Claude-CLI-not-ready Alert** (only when `isClaudeReady()` is false, using the existing `getClaudeCliStatus({ maxAgeMs: 60_000 })`): default-variant `Alert` with `TriangleAlert` icon, title, body and a primary "Open Settings" button linking to `/settings`. 24px below it. The dropzone renders disabled in this state.
3. **Dropzone** (`Card`-styled `div` from react-dropzone `getRootProps`, `p-6`, `min-h-48`, `border-2 border-dashed rounded-xl`, flex column centered, 8px internal gaps):
   - Idle: `bg-muted/40 border-border`. `ImageUp` icon (20px, muted) in an `EmptyMedia`-style 40px rounded square, Heading "Drop shelf photos here", Caption muted formats line, then primary Button "Choose photos" (calls `open()`; root `noClick` is false, so clicking anywhere on the zone also opens the picker).
   - Drag accept: `border-primary bg-primary/5`, icon `text-primary`, heading changes to "Release to upload".
   - Drag reject (any dragged item not an accepted type): `border-destructive bg-destructive/5`, heading "Only photos can be uploaded here", Caption formats line in `text-destructive`.
   - Disabled (CLI not ready): `opacity-60 cursor-not-allowed`, `aria-disabled="true"`, drops ignored, button disabled.
   - `accept`: `image/jpeg` `.jpg,.jpeg`; `image/png` `.png`; `image/webp` `.webp`; `image/heic` `.heic`; `image/heif` `.heif` (D-06; the server re-checks magic bytes). `multiple: true`. No `maxFiles`. `maxSize` 64 MB (matches the route cap).
   - Keyboard: the root is focusable (`tabIndex=0`), and Enter/Space opens the picker. It has `aria-label="Upload shelf photos"`. The hidden `<input>` comes from `getInputProps`.
4. **Upload tip** (`UploadTip`, D-03): one Caption muted line with a 16px `Lightbulb` icon, 8px below the dropzone. Always shown.
5. **Photos card** (24px below the tip): `Card` with a header row (Heading "Photos" + mono count in muted, e.g. `Photos 12`) and a `<ul>` of rows separated by `Separator`. Order: client-side rows still uploading first (in drop order), then server photos newest first. All photos are listed (single user, no pagination). `[default]`
   - **Row** (`px-4 py-3`, `flex items-center gap-4`): 48px thumbnail (server `thumbs/` once `preparing` has produced it; before that a `bg-muted` square with a 16px `Image` icon. HEIC cannot be previewed client-side, so no object-URL preview), then a `min-w-0 flex-1` text column (filename Body 500 `truncate` with full name in `title`; sub-line per the status table), then the status badge, then the row action:
     - `done` with ≥1 spine: outline Button-link "View spines" → `/spines?photo={id}`.
     - `done` with 0 spines, or `error`: outline `RescanButton` "Re-scan photo".
     - client upload failure: outline "Retry upload" (re-sends the same `File`) plus a ghost button with `X` icon and visible label "Remove from list" (`aria-label="Remove {filename} from the list"`; client-side only, nothing on the server).
     - queued / analyzing: no action.
   - Density and truncation badges (see `/spines` header) also appear on `done` rows, between the sub-line and the status badge, wrapping under the filename below 640px.
   - **Duplicate upload** (server returns `duplicate: true`): the client row is removed, the existing photo's row gets a session-only `secondary` badge "Already uploaded" (with `Copy` icon), and a toast shows the duplicate copy. Zero calls are made (INGEST-03).
   - Uploads run with concurrency 2 (02-RESEARCH Pattern 1). Further files show "Waiting to upload".
   - Below 640px: the row stacks to thumbnail + text column on top, badge and action on a second line (`flex-wrap`).
   - The list is a plain list, not a live region. Each status badge has the text visible, so screen-reader users reading the row get the current status. A single visually hidden `aria-live="polite"` region announces only terminal transitions: `{filename}: done, {n} spines found` or `{filename}: error`.

### `/spines`
1. **Title block:** Display "Spines", then the Body muted description with live counts. 32px to the filter bar.
2. **Filter bar** (`flex flex-wrap items-center gap-2`, not sticky):
   - `ToggleGroup type="single" variant="outline"`: "All" and "Needs review", each followed by a mono count (`All 142`, `Needs review 17`). Bound to nuqs `review` (`?review=1` = Needs review; absent = All). Never empty (clicking the pressed item keeps it pressed).
   - `Select` (w-64, Body) bound to nuqs `photo`: first item "All photos", then one item per photo (filename, truncated) newest first. Changing it resets scroll to top.
   - "Needs review" = active spines with any non-empty, unedited field below the confidence threshold, plus every orphaned spine (D-07, D-09, D-16).
3. **Photo sections**, one per photo with matching spines, newest photo first. Each section is a `<section aria-labelledby>`.
   - **Sticky section header** (`PhotoSection` header, sticky constants above): `flex items-center gap-2` with:
     - 40px thumbnail as a link to the vision image (`/api/files/vision/...`, `target="_blank" rel="noreferrer"`, `aria-label="Open full photo {filename}"`).
     - Text column (`min-w-0 flex-1`): filename (Body 500, `truncate`, the section's `<h2>`), sub-line Caption muted `{n} spines · {model label} · scanned {relative time}`.
     - Badges (`flex gap-2`, wrap): status badge only when not `done`; `DensityBadge` "Retake closer" when the run has density flags (D-03); "May be incomplete" when `spines.length < spine_count_estimate × 0.8` (02-RESEARCH Pattern 4). Each badge is `outline`, warning icon, foreground text, and a tooltip trigger (`<button type="button">` wrapper) with the reason copy.
     - `RescanButton` (outline, `RotateCw` icon, "Re-scan photo"). Below 640px it becomes an icon-only `size-9` button with `aria-label="Re-scan {filename}"`. Disabled with a `Spinner` and label "Analyzing…" while a run is active; the tooltip on a wrapping span gives the reason.
   - **Section body by state:**
     - Queued or analyzing, first run: three `Skeleton` cards (`h-48 w-full rounded-xl`, 16px gap) under the header.
     - Analyzing a re-scan: the existing cards stay visible and editable. The header shows the Analyzing badge. When the run finishes, the merged result replaces them on the next poll (cards keep their keys because spine IDs are stable, D-13).
     - Error with no spines: a destructive `Alert` (`CircleX`) with title "Scan failed" and the error reason as body. Re-scan stays in the header.
     - Error on a re-scan where earlier spines exist: the same Alert above the existing cards, title "Re-scan failed. Showing the previous scan."
     - Done with 0 CD spines: an `Empty` (compact, `py-8`) with `ScanSearch` icon and the "No CDs found" copy.
     - Done: active spine cards in detection order (top-to-bottom, left-to-right as Claude indexed them), 16px apart. Then, if any, a Caption-muted sub-heading `No longer detected ({n})` and the orphaned cards.
   - Sections with no matching spines under the current filter are omitted entirely (including their header).
4. **Pagination / virtualization:** none. All matching spines render (D: virtualize only past ~500 rows). Crop `<img>` uses `loading="lazy" decoding="async"`.

### Spine card (`SpineCard`, D-08, D-11)
`Card` with `p-4 gap-4` (overrides the shadcn `py-6 gap-6` default), `rounded-xl`. Order:

1. **Header row** (`flex items-center gap-2`, Caption):
   - Left: spine number `#{index}` (mono, muted), then `WorstFieldBadge` if any non-empty, unedited field is below the threshold: outline badge, warning icon, `Check {field} · {pct}%` (the lowest one; `{field}` lower-case, e.g. `Check title · 41%`). If Claude marked the detection `illegible`, the badge reads `Hard to read` instead. No badge when all fields are fine.
   - Right (`ml-auto`), the **status-badge slot** (D-11): Phase 2 fills it with `Edited · {n}` (secondary badge) when ≥1 field is edited, and with "No longer detected" (outline, warning icon) for orphaned spines. Phase 3 adds its match status here without moving anything.
2. **Crop** (`SpineCrop`, VIS-04): the muted well with the horizontal crop (layout constants above). The image is a link to the full-size crop (`target="_blank"`). `alt="Spine {index}: {raw_text}"`, or `alt="Spine {index}"` when raw text is empty. Error fallback (file missing, `onError`): the well shows a 16px `ImageOff` icon and Caption muted "Crop unavailable".
3. **Field grid** (`SpineField` ×6, grid constants above), in this order: Artist, Title, Format, Label, Catalog number, Raw text.
4. **Footer slot** (D-11): a `footer?: ReactNode` prop rendered after a `Separator` at the bottom of the card. Phase 2 passes nothing, and nothing (not even the separator) renders. For orphaned cards Phase 2 uses this slot for the action row: outline "Re-attach spine…" and ghost destructive "Dismiss spine", right-aligned, 8px gap, plus the Caption muted orphan explanation on the left.

Orphaned cards (D-16) also show the old crop and their stored field values; fields stay editable.

### Spine field (`SpineField`, D-08..D-10, D-15, REV-02)
Structure (`Field`, 4px internal gap):
- **Label row** (`flex items-center gap-1 h-4`): `FieldLabel` Caption 500 muted (`htmlFor` the input). Then, right-aligned (`ml-auto flex items-center gap-1`), in this order when present:
  - Low-confidence icon: a 16px `TriangleAlert` in `text-warning`, wrapped in a focusable `<button type="button">` that is the Tooltip trigger; `aria-label="Low confidence, {pct} percent"`.
  - Save state: `Spinner` (`size-3`) + Caption muted "Saving…" while the PATCH is in flight.
  - Edited: secondary badge "Edited", then the 24px ghost revert icon button (`Undo2`), tooltip and `aria-label` per Copywriting.
- **Control:** `Input` (Artist, Title, Format, Label, Catalog number) or `Textarea` (Raw text, 2 rows minimum). Value = `value ?? ''`. Placeholder `Not read` when the AI value is null and the user has not typed anything. `spellCheck={false}` `autoComplete="off"`.
- **Low-confidence styling** applies only when: AI value is non-empty, `confidence < threshold` (the `confidence_threshold` setting; default 0.6 until the spike tunes it), and the field is not edited. It adds `border-warning` and `aria-describedby` → a visually hidden span "Low confidence, {pct} percent. Check it against the crop." Editing the field (any saved change) removes the warning; reverting restores it.
- **Re-scan hint (D-15):** when the field is edited and the latest run's AI read differs from both `value` and the read the user originally edited, a Caption muted line appears under the control: `Sparkles` icon (warning), `Latest scan reads “{new}”`, then an underlined text button `Use new read` (Caption, foreground, `hover:text-foreground/80`) that sets `value` to that read (one PATCH). The line disappears once `value === ai_value`.
- **Editing and autosave** (02-RESEARCH Pattern 7, adapted to the Phase 1 "errors are inline" rule):
  - The field keeps a local `draft` and `isEditing`. While focused or while `draft !== saved value`, incoming poll data never overwrites the input. Inputs are never re-keyed on refetch.
  - Commit on blur. Enter commits (blurs) in Inputs; in the Raw text Textarea, Enter inserts a newline and Ctrl/Cmd+Enter commits. Escape restores the last saved value and blurs without saving.
  - On commit: trim; empty string becomes `null`; if equal to the saved value, no request. Otherwise PATCH `{ field, value }` with an optimistic `setQueryData` after `cancelQueries`.
  - On success: no toast and no "Saved" text (quiet; the "Edited" badge appearing is the confirmation).
  - On failure: **keep the draft in the input (no rollback, the user's typing is never lost)**, set `aria-invalid`, show `FieldError` (Caption, destructive) with the save-error copy, and leave the field dirty so the next blur retries. No toast.
- **Revert:** PATCH `{ field, revert: true }`. The input shows the AI value, the "Edited" badge disappears, and a toast offers `Undo revert` (which PATCHes the previous user value back). No confirm dialog.

### Re-scan (D-17, INGEST-04)
- Trigger: `RescanButton` (outline, `RotateCw`), on the `/spines` section header and on `/upload` rows that are `error` or done-with-0-spines.
- Opens an `AlertDialog` (re-scan spends subscription quota). Confirm is the `default` (accent) variant, not destructive: nothing is deleted.
- Pending: confirm shows `Spinner` + "Starting…", both buttons disabled. Success: the dialog closes, a toast shows, queries invalidate, and the header switches to "Analyzing". Failure (for example the server's "a run is already active" guard): the dialog stays open and shows the error copy as Body `text-destructive` above the buttons (`role="alert"`). Focus returns to the trigger on close.

### Re-attach and dismiss orphaned spines (D-16)
- **Re-attach spine…** opens a `Dialog` (`max-w-2xl`): title, description, then a `RadioGroup` list (`max-h-[60vh] overflow-y-auto`, 8px gap) of the photo's spines that were newly created by the latest run (unmatched new detections). Each option is a full-width bordered row (`p-4 rounded-lg border`): radio indicator, crop (`max-h-12`, `object-contain`), and the raw text (Caption muted, `line-clamp-1`). The selected row gets `ring-2 ring-primary border-primary`. Footer: ghost "Leave unattached" and primary "Re-attach spine" (disabled until a choice is made; `Spinner` + "Re-attaching…" while pending). On success: toast, the orphan card disappears, and the target card now shows the carried-over edits.
  - No candidates: the list area shows Caption muted copy (below) and the confirm button stays disabled.
- **Dismiss spine** (ghost, `text-destructive`) opens an `AlertDialog` with the destructive confirm. On success: toast, the card disappears (state `dismissed`). Focus moves to the next card's first field, or to the section header's Re-scan button if none remain.

### Loading and errors
- `src/app/upload/loading.tsx`: title Skeleton (`h-8 w-32`), dropzone Skeleton (`h-48 w-full rounded-xl`), then a Photos card Skeleton (`h-40 w-full rounded-xl`), 24px gaps.
- `src/app/spines/loading.tsx`: title Skeleton (`h-8 w-32`), filter bar Skeleton (`h-9 w-80`), then one section-header Skeleton (`h-14 w-full`) and three card Skeletons (`h-48 w-full rounded-xl`, 16px gap).
- Client fetch errors (`/api/photos` or `/api/spines` fails after data was shown): keep the last data on screen and show a destructive `Alert` at the top of the page content with the poll-error copy. Polling continues; the Alert disappears on the next success. If the first load fails, the Alert replaces the list.
- Unhandled render errors fall through to the existing `src/app/error.tsx`.

### Focus and keyboard
- Shadcn `focus-visible:ring-[3px] ring-ring/50` on everything (Phase 1). Low-confidence inputs keep the same ring width with `ring-warning/40`.
- Tab order on `/upload`: dropzone root, "Choose photos", then rows (row actions only; badges are not focusable unless they carry a tooltip).
- Tab order inside a spine card: crop link, then per field: low-confidence icon button (if any), revert button (if any), control. Then footer actions.
- Dialogs trap focus and return it to their trigger (except after Dismiss, see above).

### Motion
shadcn defaults only (dialog and tooltip fade/zoom, Sonner slide), `Spinner` rotation, and a 150ms `transition-colors` on the dropzone border. No layout animation on list updates. Everything honours `motion-reduce` (the spinner is the only exception, as shadcn ships it).
