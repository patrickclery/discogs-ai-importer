# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: autonomous. No user questions were asked. Values come from 06-CONTEXT.md (D-01..D-17, all locked), the approved 03- and 04-UI-SPEC.md, and the shipped code in `src/`. Values that no upstream source covers are researcher decisions marked `[auto]`. All on-screen copy is plain language, per the owner's preference: the words token, OAuth, queue, job, batch, master, versions endpoint, 429, 409 and rate limit never appear on screen.

**Surfaces in scope:**
- The `/spines` card layout: a new compact card (D-10), expand in place (D-11), the responsive grid (D-12) and the Compact/Detailed toggle (D-13).
- Selection: a checkbox on every card, the sticky bulk bar with "Select all shown" and the selected count (D-05, D-06).
- The bulk confirm dialog (D-07) and the per-spine bulk states: finding the pressing, preferred-country and fallback badges, the fallback line, the skipped-duplicate line, the lookup failure (D-04, D-08, D-09, D-15).
- The "Fallback" filter toggle and its empty state, plus the batch-finished toast (D-15).
- The Settings Discogs card's "Preferred country" field (D-14).
- The header status indicator's count while a bulk import runs.
- The demo twin of all of the above (D-17).

**Out of scope (deferred in CONTEXT):** shift-click range select, a preview of the resolved releases before import, undo of a bulk import.

**Unchanged from Phases 1-4:**
- The app shell, theme, fonts, every color token, the focus ring and the toast placement.
- The full spine card (header, crop, field grid, Discogs section, confirmed-match panel, action menu, duplicate dialog). Phase 6 reuses it as the expanded card and the Detailed layout, adding only a checkbox and a country badge.
- The status filter, Needs review toggle, photo Select and Retry all failed.
- `/upload`, the Search Discogs dialog, the Phase 3 search badges and the Phase 4 import badges and lines.

This spec only adds to them.

## Spacing Scale

Same scale as Phases 1-4. Declared values (multiples of 4):

| Token | Value | Tailwind | Phase 6 usage |
|-------|-------|----------|---------------|
| xs | 4px | `1` | Icon-to-text gap in badges and lines, the gap between title and details in the top match, the vertical gap between wrapped header badges (`gap-y-1`) |
| sm | 8px | `2` | Gap between the compact card's blocks (`gap-2`), between header items (`gap-x-2`), between bulk-bar items, thumb-to-text gap in the top match, bulk-bar vertical padding (`py-2`) |
| md | 16px | `4` | Compact card padding (`p-4`), grid gap between compact cards (`gap-4`), bulk-bar horizontal padding (`px-4`), the full card's padding (unchanged), the gap between the folder field and the country field in Settings |
| lg | 24px | `6` | Gap between photo sections (unchanged), the filter bar to the first section (unchanged) |
| xl | 32px | `8` | Page title block to the filter bar (unchanged) |
| 2xl | 48px | `12` | Compact top-match thumbnail (`size-12`), empty-state bottom padding (unchanged) |
| 3xl | 64px | `16` | Full-card candidate thumbnail (`size-16`, unchanged), empty-state top offset |

Layout constants:
- **Compact grid (D-12):** each photo section's cards render in `grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4`. Inside `main`'s `max-w-6xl px-6`, an xl card is about 264px wide. The "No longer detected ({n})" sub-heading and the scan Alert span `col-span-full`. Orphans follow in the same grid.
- **Detailed layout:** today's single-column stack (`flex flex-col gap-4`), unchanged.
- **Expanded compact card (D-11):** the card switches to the full `SpineCard` and spans `col-span-full`, so the 6-column field grid and the Discogs section get the full width. No `grid-flow-dense`: the spine order never changes, so a gap may remain at the end of the row before an expanded card `[auto]`. Several cards may be expanded at once. Expanded state is keyed by spine id and survives polls.
- **Compact card:** `Card` with `rounded-xl p-4 gap-2`. At xl the card is about 264px wide, leaving a 232px content column (48px thumb + 8px gap + 176px text), so four cards still fit per row at 1152px. Blocks top to bottom:
  1. Header row `flex flex-wrap items-center gap-x-2 gap-y-1 text-xs`: checkbox, `#n`, worst-field badge, `Edited · {n}`, orphan badge, then a right cluster (`ml-auto flex items-center gap-2`) with the country badge and the state badge (state badge last, Phase 4 rule).
  2. The crop: the existing `SpineCrop` well (`min-h-12`, image `max-h-32 w-full object-contain`), unchanged so the spine stays legible at 264px.
  3. The match slot (`TopMatchRow`), with a Caption 500 muted label above it: `Top match` or `Confirmed match`.
  4. At most one status line (fallback, skipped duplicate, lookup failure), Caption.
  5. Bottom row `flex justify-end`: ghost `size="sm"` `Edit spine` with `ChevronDown`.
- **Top match row:** `flex items-start gap-2`. 48px thumb (`size-12 rounded-md`, Disc3 placeholder on `bg-muted` when no cover). Text column `min-w-0 flex-1 flex-col gap-1`: title Body 500 `line-clamp-2 break-words` (full title in `title`), details Caption muted `line-clamp-2`: `{year} · {country} · {catno}`, parts omitted when absent, `No details` when all are. No external link and no Add button on the collapsed card; both live in the expanded card `[auto]`.
- **Bulk bar (D-05):** `sticky bottom-4 z-30` as the last child of the `/spines` body, so it rides at the viewport bottom and sits in flow at the end of the list (nothing is ever covered at full scroll). Surface: `Card`-style `rounded-xl border bg-card shadow-sm px-4 py-2`. Content `flex flex-wrap items-center gap-2`: select-all checkbox with its label, the selected count, ghost `Clear selection` (only when `s > 0`), the progress or last-result line (Caption muted, `min-w-0 truncate` with `title`), then the Import button pushed right with `ml-auto`. At 360px it wraps to two rows, Import on the second.
- **Filter bar row 2:** Needs review, the Fallback toggle (when shown), the photo Select, then a `ml-auto flex items-center gap-2` group holding Retry all failed (when shown) and the layout toggle, so the layout toggle is always the last item.
- **Checkbox hit area:** the 16px Radix checkbox gets `relative after:absolute after:-inset-2` for a 32px target without changing layout.

Exceptions:
- All Phase 1-4 exceptions still apply: 1px borders, `px-3` wells, `py-3` section headers, `py-2` candidate rows, 36px targets on a desktop-only tool, `pb-1` under the status group, a 360px minimum viewport.
- The checkbox's 32px hit area (below the 36px default): it sits in a dense header row, and the whole bar has a 36px select-all alternative.

## Layout & Interaction Contract

### Focal points (one per surface)
- **`/spines`, Compact:** the grid of spine crops. Each card's crop is its focal point, with the top match directly under it so a wrong read is visible at a glance (core value). The bulk bar's accent Import button is the page's single colored action.
- **Bulk dialog:** the title sentence (`Import {n} to {folder} as Canadian pressings`) and "Start import".
- **Settings Discogs card:** unchanged (the connection row). Folder and country fields are secondary.

### Card layout switch (`CardLayoutToggle`, D-13)
- `ToggleGroup type="single" variant="outline" size="sm" aria-label="Card layout"`. Items `Compact` (`LayoutGrid` icon) and `Detailed` (`Rows3` icon), each with a visible text label.
- Bound to nuqs `view` (`?view=detailed`; absent or unknown = Compact). `scroll: false`, so switching keeps the place `[auto]`. Clicking the pressed item keeps it pressed.
- Switching never clears the selection. Switching to Detailed drops the expanded-card state (every card is full there); switching back starts all collapsed `[auto]`.

### Compact card (`CompactSpineCard`, D-10, D-16)
- **Header:** `SpineSelectCheckbox`, `#n` (mono muted), `WorstFieldBadge` (D-16: low-confidence stays visible), `Edited · {n}`, the orphan badge, then the right cluster: `CountryBadge` (when the spine has a bulk import) and the state badge (`ImportStateBadge`, which falls back to the Phase 3 search badge).
- **Match slot label:** `Confirmed match` when the spine has an import in any phase (it shows the import's stored candidate: for a bulk import, the resolved pressing). `Top match` otherwise (the rank-1 candidate).
- **Match slot by state:**

| State | Match slot |
|-------|-----------|
| Has an import | `TopMatchRow` of the import's candidate snapshot. A replaced snapshot falls back to `Release {id}` with the Disc3 thumb (Phase 4 rule). |
| Has candidates, no import | `TopMatchRow` of the rank-1 candidate |
| Searching / queued / not searched / no matches / search failed / not on Discogs | A one-line Caption muted placeholder with a 16px icon instead of the row (copy below). The state badge carries the state too. |

- **Status line** (one at most, under the match slot, `flex items-start gap-1` Caption, 16px icon), in this priority:
  1. Lookup failed (D-08): `CircleX` destructive + failure copy, then an outline `size="sm"` `Retry import` (`RotateCw`) on the next line.
  2. Fallback (D-04): `TriangleAlert` warning icon, foreground text: the fallback copy.
  3. Skipped duplicate (D-09): `Copy` icon muted, muted text: the skipped copy.
  4. Finding the pressing: `Spinner`, muted text: the finding copy.
- **Bottom row:** ghost `size="sm"` `Edit spine` with `ChevronDown` (D-11's "Edit" chevron, named for what it opens), `aria-label="Edit spine #{n}"` (contains the visible label), `aria-expanded="false"`, `aria-controls` the card id. It sits right-aligned.
- **Expanded (D-11):** the card renders the full `SpineCard` exactly as Detailed does (fields, all matches, actions, confirmed panel, action menu), spanning `col-span-full`. Its last row is a right-aligned ghost `size="sm"` `Show less` with `ChevronUp` (`aria-expanded="true"`). Focus stays on the toggle across the switch. After collapsing, the card scrolls into view (`block: 'nearest'`) and focus moves to its `Edit spine`.
- Editing a field in an expanded card keeps the card expanded across polls and filter-driven refetches as long as the card stays in the list.

### Detailed layout
- Today's full `SpineCard` in a stack, plus `SpineSelectCheckbox` in the new `leading` slot (before `#n`) and `CountryBadge` before the state badge.
- `ConfirmedMatch` shows the fallback line between the confirmed box and the state line when the import used a fallback (8px gaps, same Caption style as the compact line).
- `DiscogsMatches` shows the skipped-duplicate line or the lookup-failure line (with `Retry import`) above the candidate list as the section's notice line. They take precedence over "Fields changed" and lose to "not connected" and the paused countdown `[auto]`.

### Selection (`SpineSelectCheckbox`, `useSelection`, D-05, D-06, D-16)
- **Eligible** (D-06, server-computed per spine as `bulk.eligible` plus `bulk.reason` `[auto]`): active, has a rank-1 candidate, no import in any non-failed phase, not marked not on Discogs, no bulk lookup in progress, not flagged as a skipped duplicate. Low-confidence spines are eligible (D-16).
- **Eligible checkbox:** `aria-label="Select spine #{n}"`. Space toggles. Checking does nothing else (no request).
- **Ineligible checkbox:** `disabled`, wrapped in a `tabIndex={0}` span carrying the Tooltip with the reason (Phase 4 disabled-button pattern). The checkbox has `aria-describedby` pointing to an `sr-only` copy of the reason. Reasons are in the Copywriting Contract.
- **Pruning:** the selection only ever holds ids that are shown and eligible. After every data update (poll, filter change, photo change) ids that left the list or turned ineligible drop out. So changing a filter can shrink the selection, and the count always matches what is visible `[auto]`.
- Selection lives in client state for the page session, never in the URL, and survives the layout switch.

### Bulk bar (`BulkImportBar`, D-05)
- Rendered whenever the body shows spine cards (not on empty states, the skeleton, or "No spines yet").
- **Select all shown:** a tri-state checkbox with the visible label `Select all shown ({e})`, where `{e}` = eligible spines in the current list (respecting status, Needs review, Fallback and photo filters).
  - Checked when every eligible shown spine is selected, `indeterminate` when some are, unchecked when none.
  - Clicking when unchecked or indeterminate selects all eligible shown. Clicking when checked clears the selection.
  - `{e} = 0`: disabled, with tooltip `Nothing shown can be imported`.
- **Selected count:** `{s} selected`, mono number. `aria-live="polite"` so screen readers hear the change.
- **Clear selection:** ghost `size="sm"`, shown when `s > 0`. Clears the selection; focus moves to the select-all checkbox.
- **Progress / last result line** (from the server's latest bulk run `[auto]`):
  - Running: `Spinner` + `Bulk import: {d} / {n} done`. `{d}` counts spines whose bulk step reached an end (imported, already in collection, skipped, failed).
  - Finished: muted `Last bulk import: {a} added · {f} fallbacks · {x} failed` (zero parts omitted, `{a} added` always shown). It stays until the next run starts.
  - No run yet: nothing.
- **Import button:** `default` (accent), `ListPlus` icon, label `Import {s} selected`. Opens the confirm dialog. Disabled, with a tooltip on a wrapping span, when:
  - `s = 0`: `Select spines to import first`
  - Discogs not connected: `Connect Discogs in Settings first`; reconnect needed: `Reconnect Discogs in Settings first`
  - A bulk run is still running: `Wait for the current bulk import to finish` (one run at a time `[auto]`)

### Bulk confirm dialog (`BulkImportDialog`, D-07)
- `AlertDialog` (default width). Title and body from the Copywriting Contract. When some selected spines have a low-confidence field (D-16), the body adds the low-confidence sentence; it informs, it does not block.
- **Footer:** AlertDialogCancel `Keep reviewing`, AlertDialogAction (default, accent) `Start import` (D-07's "Start", with its object named).
  - Pending: `Spinner` + `Starting…`, both buttons disabled.
  - Success: the dialog closes, the selection clears, the bar shows the running progress line, and focus moves to the select-all checkbox. No toast, unless the server skipped some spines that changed since they were picked: then the start-with-skips toast.
  - Failure: the dialog stays open, with Body `text-destructive` above the footer (`role="alert"`).
- **Keep reviewing:** closes (Escape does the same); selection kept; focus returns to the Import button.
- No preview step (D-08); the work runs in the background per spine.

### Per-spine bulk states (D-02, D-04, D-08, D-09)
- **Finding the pressing:** a new import-badge phase `resolving`: `Spinner` + `Finding pressing`. It counts under the Matched status (the spine is committed to an import) `[auto]`. The compact status line shows the finding copy.
- After resolving, the spine follows the Phase 4 states unchanged (`Waiting to import`, `Importing`, `Imported`, `Already in your collection`, `Import failed`), with the confirmed panel showing the resolved release.
- **Country badge (`CountryBadge`, D-15):** shown for any spine whose import came from a bulk run, in every phase, before the state badge. `variant="outline"`, Caption 500:
  - Preferred country (case-insensitive equal to the setting): `MapPin` muted icon + the release's country as Discogs writes it (e.g. `Canada`).
  - Otherwise: `TriangleAlert` warning icon + `Fallback: {country}` (or `Fallback: no country listed`).
  - Manual Phase 4 imports show no country badge.
- **Fallback line (D-04):** shown on the card whenever the badge says Fallback. Copy depends on why (no Canadian version, or the top match has no master).
- **Skipped duplicate (D-09):** no import is created. The spine stays Pending with the skipped line and an ineligible checkbox. The owner can still expand the card and use "Add to {folder}", which opens the Phase 4 duplicate dialog for a deliberate second copy.
- **Lookup failed** (the pressing lookup failed after its retries, or Discogs rejected the connection): review status Failed, badge `Import failed`, the failure line with `Retry import`. "Retry all failed" retries it too. Retry re-runs the lookup, then the import.
- Bulk-driven moves out of the active status filter are silent: no "moved to" toast and no focus move, because the progress line explains them `[auto]`. Counts update in place.

### Fallback filter (`FallbackFilterToggle`, D-15)
- A standalone `Toggle variant="outline"` in filter row 2, after Needs review: label `Fallback` + `Count` (muted mono). Bound to nuqs `fallback` (`?fallback=1`, scroll to top like `?photo=`). It ANDs with status, Needs review and photo.
- Rendered only when its count is above 0 or the filter is on `[auto]`, so it stays out of the way before any bulk run.
- The count covers bulk imports that used a fallback, under the photo filter, ignoring the status, review and fallback filters (same rule as the other counts).

### Batch-finished toast (D-15)
