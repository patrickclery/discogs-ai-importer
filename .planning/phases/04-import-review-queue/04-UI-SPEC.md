# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: `--auto`. No user questions were asked. Values come from 04-CONTEXT.md (D-01..D-14), 04-RESEARCH.md (Patterns 2, 4, 5, 6; Pitfalls 3, 4, 5, 8; Open Questions 1-3), the approved 01-, 02- and 03-UI-SPEC.md, and the shipped code in `src/`. Values that no upstream source covers are researcher defaults marked `[auto]`. All user-facing copy is plain language, per the owner's preference: the words token, OAuth, queue, job, lane, instance, 429, 409 and rate limit never appear on screen.

**Surfaces in scope:**
- The spine card's state badge (status slot) and the Discogs section (footer slot). This covers the "Add to {folder}" confirm, the confirmed-match panel, "Already in your collection", import failure and Retry, and "Not on Discogs".
- A new card action menu.
- The local duplicate AlertDialog (D-04).
- The `/spines` filter bar. The status ToggleGroup with counts, the separate Needs review toggle, the photo Select and "Retry all failed" (D-11, D-13).
- The `/spines` page description, the per-photo progress line in section headers (D-12) and the per-status empty states.
- The Settings "Discogs" card's "Collection folder" select (D-03).
- The header status indicator's import wording.

**Out of scope:** undoing an import, bulk accept, keyboard review, per-spine folder override, notes or custom fields on the Discogs copy, and smarter ranking (all deferred in CONTEXT).

**Unchanged from Phases 1-3:**
- The app shell, theme, fonts and every color token.
- The focus ring and the toast placement.
- The spine card's header, crop and field grid.
- `/upload`.
- The Search Discogs dialog.
- The Phase 3 search-state badges and lines.
- The candidate row content (thumb, title, details, tags, external link).

This spec only adds to them.

| md | 16px | `4` | Thumbnail-to-text gap (unchanged), the gap between the Discogs section header and its body, and the gap between the folder field and the Settings card's footer row |
| lg | 24px | `6` | Card padding on Settings (unchanged), the filter bar to the first section (unchanged) |
| xl | 32px | `8` | Page title block to the filter bar (unchanged) |
| 2xl | 48px | `12` | Empty-state vertical padding (unchanged) |
| 3xl | 64px | `16` | Candidate thumbnail (`size-16`, unchanged), empty-state top offset |

Layout constants:
- **Filter bar:** two rows inside `flex flex-col gap-2`.
  - **Row 1:** the status ToggleGroup in an `overflow-x-auto` wrapper (`-mx-1 px-1 pb-1`, so focus rings aren't clipped), with the group at `w-max`. The joined outline group never wraps. At 1152px all 7 items fit on one line, and below that the row scrolls sideways `[auto]` (CONTEXT Claude's Discretion: scroll, not wrap).
  - **Row 2** (`flex flex-wrap items-center gap-2`): the "Needs review" Toggle, the photo Select (`w-64 max-w-full`, unchanged), then "Retry all failed" pushed right with `ml-auto` when shown.
- **Candidate action row:** inside the text column, under the tags (`mt-2 flex flex-wrap items-center gap-2`). It holds "Add to {folder}". The folder name inside the label is capped at `max-w-48 truncate`, with the full name in `title`. This deviates from the Phase 3 reservation ("right edge, before the external link") `[auto]`. Under the text, the button stays next to the title it confirms and fits at 360px with long folder names.
- **Confirmed-match box:** `rounded-lg border p-2`, with the candidate content in the existing `flex items-start gap-4` layout. The state line and actions sit below it with an 8px gap.
- **Status-slot badge:** one import or search badge, last in the right-aligned slot (Phase 3 position).
- **Collection folder Select:** `w-64 max-w-full`, with a 36px ghost icon refresh button to its right (`flex items-center gap-2`).

Exceptions:
- All Phase 1-3 exceptions still apply: 1px borders, `px-3` wells, `py-3` section headers, `py-2` candidate rows, 36px targets on a desktop-only tool, and a 360px minimum viewport.
- `pb-1` (4px) under the scrolling status group, so the horizontal scrollbar doesn't touch the buttons.

## Layout & Interaction Contract

### Focal points (one per surface)
- **`/spines` page:** unchanged. The stack of spine cards, with the crop as each card's focal point. The filter bar stays quiet (outline, no accent). The Failed count in red is the only colored filter element, so failures are findable at a glance.
- **Card Discogs section, pending:** the first candidate row and its "Add to {folder}" button.
- **Card Discogs section, matched or imported:** the confirmed-match box. When a decision is needed, the "Link existing copy" button is the focal point.
- **Duplicate dialog:** the two crops and the "Add another copy" confirm.
- **Settings Discogs card:** unchanged (the connection row). The folder field is secondary.

### Review status (D-10) and the status-slot badge
`reviewStatus` comes from `GET /api/spines` (pure `reviewStatusOf()`, server-side). The card's status slot shows **one** state badge, last in the slot. It replaces the Phase 3 `SearchStateBadge` only when the import or mark state applies. Otherwise the Phase 3 search badge shows unchanged. All badges are `variant="outline"`, Caption 500.

| Review status | Sub-state | Badge |
|---------------|-----------|-------|
| imported | adopted, linked or added | `CircleCheck` (`text-success`) `Imported` |
| not_on_discogs | — | `CircleSlash` (muted) `Not on Discogs` |
| failed | latest import failed | `CircleX` (`text-destructive`) `Import failed`, label `text-destructive` |
| failed | latest search failed | Phase 3 `Search failed` (unchanged) |
| matched | import waiting (job queued, including while paused) | `Clock` (muted) `Waiting to import` |
| matched | importing (job running) | `Spinner` `Importing` |
| matched | `already_in_collection` | `TriangleAlert` (`text-warning`) `Already in your collection` |
| not_found | — | Phase 3 `No matches` (unchanged) |
| pending | — | Phase 3 badge (`Not searched` / `Queued` / `Searching` / `{n} candidates`) |

The filter label "Not found" maps to the shipped "No matches" badge. The badge wording is kept so Phase 3 copy doesn't churn `[auto]`. The body line repeats every state in words, so the badge is never the only carrier.

### Spine card: Discogs section (footer slot), by review status
The section keeps its Phase 3 structure: a header row, at most one notice line, then the body. The changes:

**Header row:**
- **Label (Caption 500, muted):**
  - `Confirmed match` when the review status is matched or imported, or when the latest import failed after a confirm.
  - `Discogs matches` otherwise.
- **Right-side actions** (`ml-auto flex flex-wrap gap-2`):

| Review status | Actions in header |
|---------------|-------------------|
| pending, not_found, failed (search) | Phase 3 actions unchanged ("Search again" / "Retry search", "Search Discogs…"), then the action menu |
| matched, failed (import) | Action menu only (hidden when it has no items, see below) |
| imported | None |
| not_on_discogs | Action menu only |

- **Action menu (`SpineActionMenu`, D-14):**
  - The trigger is a ghost icon button `size-9` with `EllipsisVertical`, `aria-label="More actions for spine #{n}"`. It is the last item in the header actions.
  - `DropdownMenuContent align="end"`. Items, Body size, each with a 16px icon:
    - `CircleSlash` "Mark not on Discogs": shown when the review status is pending, not_found or failed (search) and no import is open.
    - `Undo2` "Unmark not on Discogs": shown when marked.
  - The trigger is not rendered when the menu would be empty (imported, or an import is open). The route refuses a mark on an imported spine anyway (D-14).

**Notice line** (Phase 3 priority list, extended):
- Imported and not_on_discogs cards show no notice line. Fields changed is suppressed, and edits after an import never touch Discogs.
- For matched or failed-import cards, the notice line shows only Phase 3's "not connected" (with the reconnect variant) and the paused countdown. The paused countdown shows while an import is waiting during a Discogs pause.

**Body by review status:**

| Review status | Body |
|---------------|------|
| pending (with candidates) | `CandidateList` (Phase 3), every row with "Add to {folder}" |
| pending (no candidates) | Phase 3 lines unchanged (not searched, queued, searching, unsure media, orphaned) |
| not_found | Phase 3 no-matches line, then an action row (`mt-2`) with an outline "Mark not on Discogs" (`CircleSlash`). Any manual candidates still list below with their Add buttons. |
| failed (search) | Phase 3 failure notice plus earlier candidates (each with Add) |
| matched / failed (import) / imported | `ConfirmedMatch` (below). The other candidates are hidden. They come back only through "Change match". |
| not_on_discogs | `NotOnDiscogsLine` (below). Candidates are hidden. |

### Candidate row: "Add to {folder}" (D-01, IMP-01)
- An outline button with the `Plus` icon and the label `Add to {folder}`. `{folder}` is the cached name of the folder chosen in Settings, falling back to `Uncategorized` for id 1. It sits in the candidate action row, under the tags.
- The button sends `POST /api/spines/{id}/import {candidateId}`. The browser never sends a release id.
- **Pending:** `Spinner` + `Adding…`, and every Add button on that card is disabled (Pitfall 8, double click).
- **Success:** no toast. The section switches to `ConfirmedMatch` in the "Waiting to import" state on the next refetch, which the mutation triggers right away. Focus moves to the "Change match" button.
- **Local duplicate** (409 `duplicate`): opens `DuplicateImportDialog`. The button returns to idle.
- **Other failure:** an inline Caption `text-destructive` line under the candidate list (`role="alert"`) with the mapped copy. The button re-enables.
- **Disabled, with a tooltip on a wrapping span:**
  - When Discogs is not connected: `Connect Discogs in Settings first`.
  - When reconnect is needed: `Reconnect Discogs in Settings first`.
- Rows in the "Show all" collapsible get the same button. Rows in the Search Discogs dialog do not: that dialog still only adds candidates (Phase 3).
- Under a non-All filter, a successful Add moves the spine out of Pending, so the card leaves on the next poll. See "Leaving the current filter" below.

### Confirmed-match panel (`ConfirmedMatch`, D-01, D-02, D-05, D-09)
- A box (`rounded-lg border p-2`) holds the confirmed candidate's `CandidateRowContent` (thumb, title, details, tags, external link) with no Add button.
- Below the box (8px gap) are a state line (Caption, `flex items-start gap-1`, 16px icon) and an action row (`flex flex-wrap items-center gap-2`). The candidate data comes from the import's stored candidate. If that candidate was replaced by a re-search, the panel falls back to `Release {releaseId}` as the title with the external link, and no thumb (the Disc3 placeholder).

| Import state | State line | Actions |
|--------------|-----------|---------|
| waiting (job queued, no intent) | `Clock` muted: waiting copy | ghost `Change match` (`ArrowLeftRight`) |
| waiting while paused | `Clock` muted: Phase 3 paused copy with countdown | ghost `Change match` |
| importing (running, or intent written) | `Spinner`: importing copy | ghost `Change match`, disabled, tooltip `It's being added now. Wait for it to finish.` |
| already_in_collection | `TriangleAlert` (`text-warning`), foreground text: the already-in-collection copy, including the existing copy's folder and date | default `Link existing copy` (`Link`), outline `Add another copy` (`CopyPlus`), ghost `Change match` |
| imported (added or adopted) | `CircleCheck` (`text-success`), foreground text: imported copy | none |
| imported (linked) | `CircleCheck` (`text-success`), foreground text: linked copy | none |
| failed | `CircleX`, Caption `text-destructive`: mapped failure copy | outline `Retry import` (`RotateCw`), ghost `Change match` (enabled only when `canChangeMatch`) |

- **Change match** (D-02):
  - `DELETE /api/spines/{id}/import`, with no confirm, because nothing has reached Discogs.
  - Pending: `Spinner` + `Changing…`.
  - Success: the candidate list returns with Add buttons, and focus moves to the first row's Add button.
  - The server answers 409 when the import has already started. On 409 the inline error shows the "already being added" copy and the panel refreshes.
  - `[auto]` The cancel route must also accept `already_in_collection` rows with no intent, because no POST ever happened there.
  - On a failed import, Change match is enabled only when the API's `import.canChangeMatch` is true. That means no intent was ever written, or Discogs refused the add (404/422). Otherwise it is disabled with the tooltip `Retry first. Discogs may already have added it.` This keeps the D-07 reconcile path the only way out of an ambiguous POST.
- **Link existing copy** (D-05):
  - Pending: `Spinner` + `Linking…`, with both decision buttons disabled.
  - Success: toast `Spine #{n} linked to the copy already in your collection`, and the panel shows the linked line.
- **Add another copy** (D-05, remote):
  - Re-enqueues with `allow_duplicate`, with no extra confirm, because the decision line already says a copy exists.
  - Pending: `Adding…`.
  - Success: the panel returns to waiting.
- **Retry import** (D-13, REV-04):
  - Pending: `Spinner` + `Retrying…`.
  - Success: no toast. The panel returns to waiting. Retry reuses the same import row, which reconciles first (D-07).
- All of these actions show request errors as an inline Caption `text-destructive` line under the action row (`role="alert"`).

### Not on Discogs (`NotOnDiscogsLine`, D-14, REV-05)
- **Body:**
  - A Caption muted line with `CircleSlash`: the marked copy.
  - Then an outline `Unmark` (`Undo2`), 8px below.
  - The candidate list, Search again and Search Discogs… are hidden.
- **Mark** (from the menu or the not-found body button):
  - `POST /api/spines/{id}/not-on-discogs {flag:true}`, with no confirm, because it is reversible.
  - Success: toast `Spine #{n} marked not on Discogs` with the action `Undo`, which sends the unmark. Focus moves to `Unmark`.
- **Unmark** (`{flag:false}`):
  - Pending: `Unmarking…`.
  - Success: toast `Spine #{n} unmarked`. The section returns to its search-derived state, and focus moves to the action-menu trigger.
- Pending in the menu: the item closes the menu right away. The card shows a `Spinner` in the status slot until the refetch.
- Errors: inline Caption `text-destructive` under the header row (`role="alert"`).

### Local duplicate dialog (`DuplicateImportDialog`, D-04, IMP-03)
- An `AlertDialog` (default width) opens when the confirm route answers `duplicate`. The 409 body carries the other spine's photo filename, spine number, crop URL and whether that import is done or still in progress `[auto]`. With the crop, the owner can tell an overlapping photo of the same disc from a genuine second copy (core value: the spine image is always visible).
- **Content:**
  - Title and body (Copywriting).
  - Then two crop wells side by side (`grid grid-cols-2 gap-2`; stacked below 640px), each `max-h-12 object-contain` on `bg-muted rounded-md`. Each has a Caption muted caption under it: `This spine (#{n})` and `{photo}, spine #{m}`.
- **Footer:** AlertDialogCancel `Cancel`, and AlertDialogAction (default, accent) `Add another copy`.
  - Pending: `Spinner` + `Adding…`, both buttons disabled. This resends with `allowDuplicate:true`.
  - Success: the dialog closes, and focus moves to the card's "Change match".
  - Failure: the dialog stays open, with Body `text-destructive` above the footer (`role="alert"`).
- **Cancel:** closes, and focus returns to the Add button that opened the dialog.

### `/spines` filter bar (D-11, D-13, REV-03)
- **Row 1, status filter (`ReviewStatusFilter`):** `ToggleGroup type="single" variant="outline" aria-label="Filter by status"`.
  - Seven items in this order: `All`, `Pending`, `Matched`, `Imported`, `Not found`, `Not on Discogs`, `Failed`. Each is followed by its count (`Count`, mono muted; Failed in `text-destructive` when above 0).
  - Bound to nuqs `status` (`?status=pending|matched|imported|not_found|not_on_discogs|failed`; absent = All). An unknown value reads as All. The group is never empty: clicking the pressed item keeps it pressed.
  - Items with 0 stay enabled. Clicking one shows its empty state.
  - Changing the status filter resets scroll to the top (`scroll: true`, like `?photo=`).
- **Row 2:**
  - **Needs review:** a standalone `Toggle variant="outline"` with the label `Needs review` and its count, bound to the existing `?review=1`. It ANDs with the status filter.
  - **Photo Select:** unchanged.
  - **Retry all failed (`RetryAllFailedButton`, D-13):**
    - An outline `RotateCw` button with `ml-auto`, rendered only when `counts.failed > 0`.
    - It sends one bulk `POST /api/spines/retry-failed` `[auto]` (Open Question 3), which covers the photo filter in view.
    - Pending: `Spinner` + `Retrying…`, disabled.
    - Success: toast with the retried count, plus a second sentence when some were skipped because Discogs isn't connected.
    - When nothing could be retried: an inline Caption muted line beside the button instead of a toast.
    - Request errors: inline Caption `text-destructive` (`role="alert"`).
- **Counts** (`counts.byStatus` from `GET /api/spines`):
  - They cover active and orphaned spines under the current photo filter, and ignore the status and review filters, so every count stays visible while filtering.
  - The Needs review count also ignores the status filter (02-12 semantics).

### Leaving the current filter `[auto]`
- When an owner action changes a spine's review status and the active status filter no longer includes it, the card leaves on the next poll. This covers Add, Change match, Mark, Unmark, Link, Retry and Add another copy, under any filter other than All.
- To explain the jump, the action shows the toast `Spine #{n} moved to {Status label}` with the action `Show`, which switches the filter to that status.
- Focus moves to the next card's Discogs section header (its first focusable control). If there are no cards left, focus moves to the status filter's pressed item.
- Background transitions (an import finishing, a search completing) leave silently. They are expected progress, and the counts update in place.

### `/spines` page header and sections (D-12)
- **Description:** `{n} spines from {m} photos · {i} imported · {l} left. Changes save when you leave a field.`
  - `l` = pending + matched + not found + failed, which is everything not imported and not marked. The numbers are mono.
  - When `l = 0` and `n > 0`, the middle reads `· every spine is imported or marked`.
- **Section sub-line**, for a done photo with at least 1 spine: `{i} / {n} imported · {model label} · scanned {relative time}`.
  - It replaces `{n} spines ·`. `{n}` = the photo's active + orphaned spines, regardless of filters.
  - It updates with each poll. No progress bar.
  - Active and error photos keep their Phase 2 sub-lines.
- **Orphaned imported spines** (Pitfall 5) list under "No longer detected" as today, with their confirmed-match panel. Their "Dismiss spine" is disabled while a non-failed import exists, with the tooltip `Spines with a match being added or already added can't be dismissed.`

### Per-status empty states
- Each empty state is an `Empty` with `pt-16 pb-12` (the existing filter-empty layout), a 20px icon, a Heading title, a Body muted description and one outline action. The copy is in the Copywriting Contract.
- The action is `Show all spines` (sets status to All and keeps photo and review). The only exception is when Needs review is also on and the combination is empty: then use the combined copy, whose action clears both.

| Filter | Icon |
|--------|------|
| Pending | `ListChecks` |
| Matched | `Clock` |
| Imported | `Library` |
| Not found | `SearchX` |
| Not on Discogs | `CircleSlash` |
| Failed | `CircleCheck` (muted, not success-colored) |
| Status + Needs review | `ListFilter` |

### Settings: Collection folder (`CollectionFolderField`, D-03, IMP-02)
- **Placement:** inside the connected Discogs card's account section, after the "Connected as" lines and before the Test / Disconnect footer row, separated by 16px. It is shown only when connected. When not connected the field is absent, because there is no folder list to load.
- **Field:**
  - `FieldLabel` "Collection folder".
  - A row with a `Select` (`w-64 max-w-full`, Body) and a ghost icon button `size-9` (`RefreshCw`, `aria-label="Reload folders from Discogs"`, tooltip `Reload folders`).
  - Then a `FieldDescription`.
  - Options: one per folder with id ≥ 1, in Discogs order: `{name}` followed by a muted mono count (`{count}`). Folder 0 "All" is never listed. A single option (Uncategorized only, today's account) is shown, not hidden.
- **Load:**
  - `GET /api/discogs/folders` returns the cache.
  - Opening Settings with no cache, or a cache older than 1 h, triggers `POST {refresh:true}` inline `[auto]` (Open Question 1, Test-connection precedent).
  - While loading with no cache: the Select is disabled, and the trigger shows `Spinner` + `Loading folders…`.
  - The refresh button shows a spinning icon while pending.
- **Save:**
  - Saves on change, like `ModelSelect`. The Select is disabled while pending.
  - Toast `Imports now go to {folder}`.
  - Failure: inline `FieldError` with the save-error copy. The Select reverts to the saved value.
- **Load failure:** an inline Caption `text-destructive` line under the field (`role="alert"`) with an underlined text button `Try again`. The Select keeps showing the saved folder, falling back to `Uncategorized`.
- **Saved folder missing** from a fresh list: a Caption line with a `TriangleAlert` icon (`text-warning`) and foreground text, under the field (Copywriting). Imports go to Uncategorized until another folder is picked `[auto]`.
- Each import records the folder it used, so changing the setting never moves existing imports.

### Header status indicator
- `GET /api/status` → `discogs` gains `imports: { left, failed }`. `left` = queued + running `add_to_collection` jobs, a subset of `backlog`.
- **Text:** when `backlog ≥ 1` and every item in it is an import (`left === backlog`), the not-paused texts read `Adding to Discogs · {d} left` (alone) or `Working · {a} queued · Adding to Discogs · {d} left` (with vision work). Mixed backlogs and the paused texts keep the Phase 3 wording.
- **Tooltip:** a new line under the Discogs line, shown only when `left + failed > 0`: `Collection — {left} being added, {failed} failed`.
- The `· {f} failed` suffix still counts vision failures only.

### Polling
- `discogsActive` in `SpinesResponse` also turns true while any listed spine's import job is queued or running. In that case, refetch every 3000ms (Phase 3 rule; the fastest applicable interval wins).
- `already_in_collection` and `failed` imports do not keep polling alive.
- After any import, mark, retry or folder mutation succeeds: invalidate `['spines']` (and the candidates query for that spine), then dispatch `app:status-refresh`.

### Loading and errors
- The `/spines` loading skeleton gets a second filter-row skeleton: `h-9 w-full max-w-3xl` for the status group, then the existing `h-9 w-80`.
- The settings loading skeleton is unchanged.
- Poll errors keep the Phase 2 "Couldn't refresh" Alert. The last import states stay on screen.
- Every error is inline and persistent. Toasts are for success only (Phase 1 rule).

### Focus and keyboard
- The shadcn `focus-visible:ring-[3px] ring-ring/50` applies everywhere.
- The ToggleGroup uses Radix roving focus: arrow keys move, and Space or Enter presses.
- Tab order in the filter bar: status group, Needs review, photo Select, Retry all failed.
- Tab order inside a card's Discogs section:
  1. The header actions (Search again / Retry search, Search Discogs…, the action-menu trigger).
  2. Per candidate row: Add, then the external link.
  3. Show all.
  4. In the confirmed panel instead of the rows: the external link, then the state actions in their visual order.
- The dropdown menu and AlertDialog trap focus and return it to their trigger, except where this spec moves focus after a success.
- Every action button that changes state is a real `<button>` with a visible text label. The only icon-only buttons are the menu trigger and the folder refresh, and both carry `aria-label`s.

### Motion
shadcn defaults only: the dropdown and dialog fade/zoom, the Sonner slide, `Spinner` rotation and the status-dot pulse. There is no animation when a card changes state or leaves a filter.

## Copywriting Contract

Placeholders in `{braces}` are interpolated. `{folder}` is the cached folder name, falling back to `Uncategorized`. `{n}` in `#{n}` is the 1-based spine number (`spineNumber()`). Pluralize every count (`1 spine` / `2 spines`, `1 copy` / `2 copies`). Dates use `Intl.DateTimeFormat` with `{ day:'numeric', month:'short', year:'numeric' }` (e.g. `30 Nov 2015`).
