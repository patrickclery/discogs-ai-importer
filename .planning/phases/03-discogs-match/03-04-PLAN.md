## Phase Goal

**As the** owner cataloguing my CDs, **I want to** connect my Discogs account and see, for every CD spine, candidate Discogs releases I can recognize, with manual search and a pasted release link for the ones auto-search misses, **so that** I can find the right release for every disc without Discogs rate limits ever losing work.

**This plan's slice:** on /spines, each card says where its Discogs lookup stands and lists the releases found, right under the crop and fields, so the owner can compare them with the real spine. The page keeps refreshing while lookups run. Plan 03-05 serves the cover images, Plan 03-06 adds Search again and Retry, and Plan 03-07 adds the Search Discogs… dialog.

<objective>
Expose search state and candidates in the /spines read model and render them in the existing card slots: the search-state badge in the status slot and the Discogs matches section (top 3 plus a lazy Show all) in the footer, with the not-connected notice, every state line and polling while searches run.

Purpose: DISC-04 (what each candidate shows) and the visible half of DISC-03; D-04 (no connection notice), D-10 order, D-11 states, D-12 list.
Output: SpineDto and SpinesResponse fields, src/server/discogs/queries.ts, the candidates GET route, seven components (plus shadcn collapsible), polling helper and tests.
</objective>
