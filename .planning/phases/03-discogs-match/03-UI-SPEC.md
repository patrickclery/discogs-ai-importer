# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: `--auto`. No user questions were asked. Values come from 03-CONTEXT.md (D-01..D-16), 03-RESEARCH.md (Patterns 1-7, Pitfalls 3, 4, 5, 7, 8), the approved 01-UI-SPEC.md and 02-UI-SPEC.md, and the shipped code in `src/`. Values not covered upstream are researcher defaults marked `[default]`. All user-facing copy is plain language, per the owner's preference: no OAuth, token, queue, job, lane or 429 wording on screen.

**Surfaces in scope:**
- The Settings "Discogs" card (connect, connected, test, disconnect, reconnect, paste-code fallback, callback URL).
- The header status indicator's Discogs segment.
- A "not connected" notice on `/spines`.
- The spine card's search-state badge (status slot) and Discogs matches section (footer slot).
- The "Search Discogs…" dialog, with free-text search and a pasted release link or number.

**Out of scope:**
- Choosing or confirming a candidate, and adding to the collection (Phase 4).
- Already-in-collection warnings.
- Status filters and counts for match and import states (REV-03).
- Marking a spine "Not on Discogs".
- Removing a candidate.
- Smart ranking beyond the catalog-number pin.
- Keyboard review and bulk actions.

Nothing in this phase writes to the owner's Discogs account.

**Unchanged from Phases 1 and 2:**
- The app shell, the theme (follows the OS), the fonts and every color token.
- The focus ring and the toast placement.
- The spine card's header, crop and field grid.
- The `/upload` page and the `/spines` filter bar.

This spec only adds to them.

## Spacing Scale

Same scale as Phases 1 and 2. Declared values (multiples of 4):

| Token | Value | Tailwind | Phase 3 usage |
|-------|-------|----------|---------------|
| xs | 4px | `1` | Icon-to-text gap in badges and buttons, the gap between a candidate's title line and its details line |
| sm | 8px | `2` | Gap between buttons, between badges, and between the matches header label and its actions. Gap between the dialog's input and its Search button. Vertical padding of candidate rows (`py-2`). |
| md | 16px | `4` | Thumbnail-to-text gap in candidate rows (`gap-4`). Gap between the orphan row and the matches section in a card footer. Gap between the dialog's spine reference, search form and results. Gap between sections inside the Discogs card. |
| lg | 24px | `6` | Card padding (`p-6`) and the gap between Settings cards (Phase 1) |
| xl | 32px | `8` | Page title block to first content (unchanged) |
| 2xl | 48px | `12` | Empty-state vertical padding (unchanged) |
| 3xl | 64px | `16` | Candidate thumbnail size (`size-16`), the empty-state top offset |

Layout constants:
- **Candidate thumbnail:** 64x64 (`size-16`), `rounded-md object-cover bg-muted`. The server caches it at 128px max (WebP) for 2x displays. The `<img>` has `width={64} height={64} loading="lazy" decoding="async"` so lazy loading never shifts layout.
- **Matches in the card:** the inline list shows at most 3 candidate rows. "Show all {n}" expands to all stored candidates (at most 10 auto, plus any added manually).
- **Search dialog:** `max-w-2xl` (matches the Re-attach dialog). The results area is `min-h-40 max-h-[50vh] overflow-y-auto`. The spine reference crop is `max-h-12 object-contain` on the muted well.
- **Callback URL well:** the Phase 1 value-well style (`bg-muted rounded-md px-3 py-2 font-mono text-xs break-all`), with a 36px ghost icon button on its right.

Exceptions:
- All Phase 1 and Phase 2 exceptions still apply: 1px borders, `px-3` value wells, `py-3` section headers, 36px targets on a desktop-only tool, and a 360px minimum viewport.
- `py-2` (8px) candidate rows are allowed because the 64px thumbnail sets the row height.

## Layout & Interaction Contract

### Focal points (one per surface)
- **Settings, Discogs card:** the connection state row. Before connecting, the "Connect Discogs" accent button (or "Save credentials" if keys are missing). After connecting, "Connected as {username}".
- **`/spines`:** unchanged. The stack of spine cards, and within each card the crop. The matches section sits below the fields and reads as secondary: Caption label, muted details and no accent.
- **Matches section:** the first candidate row. It is pinned, so a "Catalog number match" or "Added manually" row is the one the eye lands on.
- **Search dialog:** the result list, with "Add to candidates" as the single emphasized control.

### Settings: "Discogs" card (D-01..D-04, DISC-01)
The card replaces the Phase 1 "Discogs app" card in the same position (second, after Claude CLI). It is server-rendered from `{ connected, username, needsReconnect, pendingConnect, callbackUrl }` only. Tokens and the request-token secret never reach the page (D-02).

**Header:**
- `CardTitle` "Discogs" (Heading).
- A right-aligned connection badge (`outline`):

| Connection state | Badge |
|-----------------|-------|
| not connected | "Not connected" (no icon) |
| connected | `CircleCheck` (`text-success`) "Connected" |
| reconnect needed (latest searches got `auth_failed`) | `TriangleAlert` (`text-warning`) "Reconnect needed" |

`CardDescription`: the copy below, with the developers link.

**Body**, top to bottom, sections separated by `Separator`, with a 16px gap:
1. **Connect result notice** (`DiscogsConnectNotice`). It shows only while the URL has `?discogs=`:
   - `connected`: no Alert. Show a toast once, then `router.replace('/settings')` to drop the param.
   - `denied`: a default Alert (`Info` icon).
   - `expired`: a default Alert (`Clock` icon).
   - `error`: a destructive Alert (`CircleX`).
   - The copy is below. A denied, expired or error Alert stays until the next Connect click or a reload without the param.
2. **Reconnect Alert** (only when reconnect is needed): a default Alert with the `TriangleAlert` icon in `text-warning`, title and body below, and a primary "Reconnect Discogs" button inside it. In this state the account section's Connect button is not shown, so there is only one accent button.
3. **Credentials:** the existing `DiscogsCredentials` (two `SecretField`s, Phase 1 state machine) unchanged. Its Clear confirm body gains one sentence (Copywriting).
4. **Callback URL** (`CallbackUrlField`):
   - A Label "Callback URL" and the value well showing `http://{host}/api/discogs/callback`, built from the current request's Host (D-03).
   - A ghost icon button (`Copy`, `aria-label="Copy callback URL"`, tooltip "Copy"). On click it copies the URL and shows a toast "Callback URL copied".
   - A `FieldDescription` (copy below).
5. **Account section:**
   - **Not connected:** Body muted text (copy below), then a row (`flex flex-wrap items-center gap-2`) with "Connect Discogs" (`LogIn` icon).
     - Disabled with a tooltip on a wrapping span when either consumer value is unset.
     - Pending: `Spinner` + "Opening Discogs…", disabled.
     - On success, `window.location.assign(authorizeUrl)` sends the browser to discogs.com.
     - On failure, an inline Body `text-destructive` line under the row (`role="alert"`) with the mapped copy. No toast.
   - **Paste-code fallback** (`PasteCodeForm`):
     - Rendered under the Connect row only while `pendingConnect` is true (a connect was started in the last 15 minutes and not finished).
     - A `Field`: Label "Code from Discogs", `Input` (`autoComplete="off" spellCheck={false}`, placeholder `Code`), the description below, and an outline "Finish connecting" button. Enter submits.
     - Pending: "Connecting…".
     - Errors use an inline `FieldError` (copy below).
     - On success the page revalidates to the connected state and the "Connected as" toast shows.
   - **Connected:**
     - Body: `Connected as ` + the username (Body 500, accent link, `target="_blank" rel="noreferrer"`).
     - Below it, Caption muted: the "what happens next" line (copy below).
     - Then a footer row (`flex flex-wrap items-center justify-between gap-2`):
       - Left: outline "Test connection" (`PlugZap`) with its inline result (`role="status" aria-live="polite"`, Body, `CircleCheck` `text-success` or `CircleX` `text-destructive`, the same pattern as Test Claude). Pending: `Spinner` + "Testing…". The result persists until the next test.
       - Right: ghost `text-destructive` "Disconnect Discogs" (`Unplug` icon), which opens the AlertDialog.
6. **Disconnect confirm** (AlertDialog): destructive confirm. Pending: "Disconnecting…", both buttons disabled. On success: toast, the card returns to not connected, and the matches sections on `/spines` show the not-connected line on the next poll. On failure the dialog stays open with an inline destructive error.

### Header status indicator (D-07, Pitfall 8)
The existing `StatusIndicator` keeps its states, dot colors, 5s polling and tooltip mechanics. `GET /api/status` adds `discogs: { connected, backlog, pausedUntil, failedSpines }`, where `backlog` is the queued + running count on the `discogs` lane.

Text, by state (`a` = queued + running on the `anthropic` lane, `d` = Discogs backlog; numbers are mono `tabular-nums`):

| a | d | Paused? | Text |
|---|---|---------|------|
| 0 | 0 | — | `Worker idle` |
| ≥1 | 0 | — | `Working · {a} queued` |
| 0 | ≥1 | no | `Searching Discogs · {d} left` |
| 0 | ≥1 | yes | `Discogs paused · {d} left` |
| ≥1 | ≥1 | no | `Working · {a} queued · Discogs {d} left` |
| ≥1 | ≥1 | yes | `Working · {a} queued · Discogs paused` |

- The dot pulses while `a + d ≥ 1` (unchanged rule: Busy).
- The `· {f} failed` suffix now counts failed `anthropic` jobs only. Discogs failures are spines whose latest search failed (`failedSpines`), shown only in the tooltip, so retried searches no longer inflate a forever-growing count.
- The tooltip's Discogs line replaces the Phase 1 one: `Discogs — {d} left, {failedSpines} searches failed`. A second line appears only when paused: `Discogs asked the app to slow down. Searching picks up again in {s} seconds.` (`s` counts down client-side from `pausedUntil`, and the line is removed at 0). When not connected, the Discogs line reads `Discogs — not connected`.
- Below 640px, only the dot shows (unchanged).

### `/spines`: not-connected notice (D-04)
- When `discogs.connected` is false and at least one spine exists, a default `Alert` (`Unplug` icon) sits between the filter bar and the first photo section, 24px above the sections. It has the title and body below and an outline "Open Settings" button (link to `/settings`).
- It is not dismissible. It disappears once connected.

### Polling (Pitfall 4)
- `SpinesResponse` gains `discogsActive: boolean` (any search for a listed spine is queued or running).
- `refetchInterval` keeps the Phase 2 rules (1500ms while a photo is active, 3000ms after a failed poll) and adds **3000ms while `discogsActive` is true**. The fastest applicable interval wins. Otherwise polling stops (`false`).
- Each spine in the response carries only its search summary and its top 3 candidates.
- After any search or add request succeeds, invalidate `['spines']`, invalidate that spine's `['discogs-candidates', spineId]`, and dispatch `app:status-refresh`.

### Spine card: search-state badge (status slot, D-11)
`SearchStateBadge` is appended **last** in the existing right-aligned status slot (after "Edited · {n}" and "No longer detected"), so Phase 2 badges don't move. All badges are `variant="outline"`, Caption 500.

| State | Condition | Badge |
|-------|-----------|-------|
| Not searched | No search row, or not connected | `Circle` (muted) `Not searched` |
| Queued | Latest search's job is queued, including while paused | `Clock` (muted) `Queued` |
| Searching | Latest search's job is running | `Spinner` `Searching` |
| N candidates | Latest auto/again search done with ≥1 result, or any manual candidate exists | `Disc3` (muted) `{n} candidates` (`1 candidate` singular; `n` mono). `n` counts all stored candidates (auto + manual, deduped by release). |
| No matches | Latest search `no_match` and no manual candidates | `SearchX` (muted) `No matches` |
| Search failed | Latest search `failed` or `auth_failed`, or its job failed | `CircleX` (`text-destructive`) `Search failed`, label `text-destructive` |

Below 640px the status slot wraps under `#n` (existing `flex` behavior). The badge is never the only carrier of the state, because the matches section repeats it in words.

### Spine card: Discogs matches (footer slot, D-12..D-16)
**Composition (Pitfall 3):**
- `SpineView` always passes a footer for active and orphaned spines: `<div className="flex flex-col gap-4">{orphaned && <OrphanFooter/>}<DiscogsMatches/></div>`.
- `OrphanFooter` is exported from `spine-card.tsx`, and the `footer ?? <OrphanFooter/>` fallback stays for other callers.
- Every card therefore renders the separator and the matches section, because every card offers "Search Discogs…" (D-15).

**Header row** (`flex flex-wrap items-center gap-2`):
- Left: Caption 500 muted label `Discogs matches`.
- Right (`ml-auto flex flex-wrap gap-2`), in this order when present:
  - Outline "Search again" (`RotateCw`). Shown when `fieldsChanged` is true (D-14) and the latest search is not queued or running.
  - Outline "Retry search" (`RotateCw`). Shown instead of "Search again" when the latest search failed (D-06).
  - Outline "Search Discogs…" (`Search` icon). Always shown. Disabled when not connected, with a tooltip on a wrapping span.
  - Pending (request in flight): the clicked button shows `Spinner` + "Queuing…" and is disabled. A success needs no toast, because the badge flips to Queued. A failure shows an inline Caption `text-destructive` line under the header row (`role="alert"`).
- Below 640px the buttons wrap to a second line, right-aligned.

**Notice line** (under the header, Caption muted, `flex items-start gap-1`, 16px icon). At most one shows, in this priority:
1. Not connected: `Unplug` icon, `Connect Discogs to find matches.` and an accent text link `Open Settings` (`/settings`).
2. Fields changed (D-14): `PencilLine` icon (`text-warning`), `Fields changed since last search.`. The "Search again" button is in the header.
3. Paused while queued: `Clock` icon, the paused copy with a client-side seconds countdown.
4. Search failed: `CircleX` icon, Caption `text-destructive`, the mapped failure reason.

**Body, by state** (16px below the header):

| State | Body |
|-------|------|
| Not searched, connected, CD spine | Caption muted line: the "not searched yet" copy |
| Not searched, spine is `unsure` media | Caption muted line: the "may not be a CD" copy |
| Not searched, orphaned spine | Caption muted line: the "orphaned" copy |
| Queued (no earlier candidates) | Caption muted line with `Clock` icon: the queued copy |
| Searching (no earlier candidates) | Caption muted line with `Spinner`: `Searching Discogs…` |
| Queued or searching with earlier candidates | The earlier candidate list stays fully visible. The badge carries the state. No skeletons and no dimming. |
| N candidates | `CandidateList` |
| No matches | Caption muted line: the no-matches copy (any manual candidates still list below it) |
| Search failed with earlier candidates | The earlier list stays, under the failure notice line |

**`CandidateList`** (`<ul>` with `divide-y`, each `<li>` a `CandidateRow`):
- **Order** (D-10, D-15, D-16):
  1. Manual candidates, newest first.
  2. Candidates whose normalized catno equals the spine's (`catnoMatch`).
  3. The rest in Discogs order.
  - Rows are deduped by release id. If a release is both manual and auto, it shows once with "Added manually".
- **Inline:** the first 3 rows.
- **"Show all {n}":** when the total is above 3, a `Collapsible` holds the rest.
  - The trigger is a ghost button under the list, Caption: `Show all {n}` with `ChevronDown`. When open: `Show fewer` with `ChevronUp`.
  - Opening lazily GETs `/api/spines/{id}/candidates` (query `['discogs-candidates', spineId]`). The rows beyond the first 3 render from that response.
  - Loading: 2 `Skeleton` rows (`h-16 w-full rounded-md`).
  - Error: a Caption `text-destructive` line (copy below) with an underlined text button "Try again".
  - Open/closed state is local and not persisted. Collapsing returns focus to the trigger.

**`CandidateRow`** (`flex items-start gap-4 py-2`):
1. **`CandidateThumb`:** `<img src="/api/discogs/thumb/{candidateId}">` at 64x64, `alt=""` (the title next to it carries the meaning).
   - When there is no thumb URL, or on `onError`: the same 64px `bg-muted rounded-md` square with a 20px `Disc3` icon (muted). Never a broken-image glyph.
2. **Text column** (`min-w-0 flex-1 flex flex-col gap-1`):
   - **Title:** Body 500, the Discogs combined `title` verbatim, `line-clamp-2`, with the full text in `title`.
   - **Details:** Caption muted. `{year} · {country} · {labels} · {catno} · {format}`.
     - A missing part is dropped along with its separator.
     - Labels are deduped, and at most 2 show (joined `, `). Beyond that, append ` +{k} more`.
     - Format comes from `formats[0]`: `{qty>1 ? qty + '×' : ''}{name}`, then its `descriptions` joined `, ` (e.g. `CD, Album, Reissue`, `2×CD, Compilation`).
     - If every part is missing: `No details on Discogs`.
   - **Tags** (`flex flex-wrap gap-1`, only when present):
     - `outline` badge with `Hash` icon (muted), `Catalog number match`.
     - `secondary` badge `Added manually`.
3. **External link:** a ghost icon button `size-9` (`ExternalLink`), as an `<a href="https://www.discogs.com/release/{releaseId}" target="_blank" rel="noreferrer">`. The URL is built from the numeric id only. `aria-label="Open {title} on discogs.com"`, tooltip `Open on discogs.com`.

Reserved for Phase 4: a selection/confirm control at the row's right edge, before the external link. Phase 3 renders none (D-12). Rows are not clickable or selectable.

### Search Discogs dialog (`DiscogsSearchDialog`, D-15, DISC-06)
The trigger is "Search Discogs…" in the matches header. It is a `Dialog` at `max-w-2xl`. Focus moves to the input on open, with the prefilled text selected.

1. **Header:** title and description (copy below).
2. **Spine reference:** the spine's crop (`max-h-12 object-contain`, muted well, `alt="Spine {n}"`), so the owner compares results with the real spine (core value).
3. **Search form** (`<form>`, `flex gap-2`, items-start):
   - `Field` with a visually hidden Label "Search Discogs", an `Input` (`flex-1`), and a `FieldError` under it.
   - Prefill: the current artist and title values joined with a space. If both are empty, the catalog number. If that is empty too, empty.
   - An outline "Search Discogs" button (`Search` icon), which submits. It is disabled while the trimmed value is empty. Enter submits.
   - Client-side `parseDiscogsRef` runs on submit:
     - master link or `[m…]`: no request. `FieldError` with the master copy, `aria-invalid`.
     - release link, `[r…]` or bare number: `POST /api/spines/{id}/search {mode:'ref', value}`.
     - anything else: `{mode:'text', value}`.
     - The server re-parses and is authoritative.
4. **Results area** (`min-h-40 max-h-[50vh] overflow-y-auto`, with a polite visually hidden `role="status"` that announces `{n} results` or the no-results copy when a search finishes). It polls `GET /api/discogs/searches/{searchId}` every 1500ms until the search is terminal.

| State | Content |
|-------|---------|
| Before the first search | Caption muted, centered: the "before search" copy |
| Queued | `Clock` icon + Caption muted: the queued copy. If paused, the paused copy with countdown. |
| Searching | `Spinner` + Caption muted `Searching Discogs…` |
| Text results | `RadioGroup` of result rows (8px gap). Each row is a full-width bordered option (`p-2 rounded-lg border`, `flex items-start gap-4`): radio indicator, then the `CandidateRow` content (thumb, title, details, external link). Selected: `ring-2 ring-primary border-primary`. At most 25 results `[default]`. When Discogs reports more, a Caption muted line under the list shows the "first 25" copy. |
| Release found (link or number) | One option row of the same shape, **not preselected** (Pitfall 5), with a Caption muted line above it: the check-it copy |
| Already a candidate | The row shows a `secondary` badge `Already listed` and stays selectable. Adding it pins it as "Added manually". |
| No results | Caption muted: the no-results copy with the query |
| Release not found (404) | Caption `text-destructive`: the not-found copy |
| Failed | Caption `text-destructive`: the failure copy. Searching again is the retry. |

5. **Footer:**
   - Ghost "Close search" (closes).
   - Primary "Add to candidates", disabled until a row is selected. Pending: `Spinner` + "Adding…", both buttons disabled.
   - Posts `{searchId, releaseId}` to `POST /api/spines/{id}/candidates`. The client never sends candidate data.
   - On success: the dialog closes, a toast shows, and focus returns to the "Search Discogs…" trigger. The card's list now shows the release pinned first with "Added manually".
   - On failure: the dialog stays open, and the error copy shows as Body `text-destructive` above the footer (`role="alert"`).
6. Closing the dialog while a search is queued doesn't cancel it. Its results stay on the search row and are simply not shown. Reopening starts fresh.

### Loading and errors
- `settings/loading.tsx` is unchanged: three card skeletons still cover the page, and the Discogs card is still the second card.
- The `/spines` loading skeleton is unchanged. Cards render their matches section from the same `/api/spines` payload, so there is no separate loading state per card.
- Poll errors use the existing page-level "Couldn't refresh" Alert (Phase 2). The last candidates stay on screen.
- Every error is inline and persistent. Toasts are for success only (Phase 1 rule).

### Focus and keyboard
- The shadcn `focus-visible:ring-[3px] ring-ring/50` applies everywhere.
- Tab order inside the card footer:
  1. Orphan actions (if any).
  2. "Search again" / "Retry search".
  3. "Search Discogs…".
  4. Each candidate row's external link.
  5. "Show all {n}".
  - Candidate rows themselves are not focusable.
- The dialog traps focus. Arrow keys move between radio options (Radix). Focus returns to the trigger on close.
- On the Settings card, after a Disconnect, focus moves to "Connect Discogs". After "Finish connecting" succeeds, focus moves to "Test connection".

### Motion
shadcn defaults only: dialog and tooltip fade/zoom, the Collapsible's height (instant under `motion-reduce`), the Sonner slide, `Spinner` rotation and the status-dot pulse. There is no animation when candidates arrive or reorder.
