Planner finding about "Clear value" (verified 2026-10-25): `AlertDialogAction` renders `<Button variant="default" asChild>` around the Radix action. Radix Slot joins the two class strings without merging them, so the DOM carries both the default variant's primary fill and the override's destructive fill. In the compiled CSS the primary fill rule comes after the destructive one (`.bg-destructive` at byte 21310 and `.bg-primary` at 21889 in today's build), so primary wins. "Clear value" therefore renders as a primary-colored button today. Swapping only its text class, as the UI-SPEC C-1 row says, would leave it mauve after Phase 7. The UI-SPEC contract says all three destructive confirms are "filled red with base text", so the fix is `variant="destructive"`, which is exactly how "Dismiss spine" and "Disconnect Discogs" are already written. The C-1 outcome (base text on red, 7.08:1) is the same.

The utilities `bg-primary-hover`, `text-primary-hover` and `text-destructive-foreground` exist because 07-01 added `--color-primary-hover` and `--color-destructive-foreground` to `@theme inline`.
</context>
