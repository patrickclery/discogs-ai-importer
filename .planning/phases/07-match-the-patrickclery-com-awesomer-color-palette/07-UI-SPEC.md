# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: autonomous. No user questions were asked. Values come from 07-CONTEXT.md (all decisions locked), 07-PALETTE-REFERENCE.md (tokens captured from the live site) and the shipped code in `src/`. Values that no upstream source covers are researcher decisions marked `[auto]`. Contrast ratios were computed with the WCAG 2.x relative-luminance formula. Translucent values were flattened over the surface they sit on before measuring.

**Phase in one line:** recolor the app and the demo site to Catppuccin Mocha, dark only, by remapping the shadcn tokens in `src/app/globals.css`. This phase changes only colors. It adds no features, layouts, copy or fonts.

**Surfaces in scope:** every screen (`/upload`, `/spines` in Compact and Detailed, `/settings`, every dialog, menu, select, tooltip and toast) and the demo export, because they all read the same tokens.

**Unchanged from Phases 1-6:** all copy, layout, spacing, typography (Geist Sans and Geist Mono), icons, motion, component structure, URL state, and the "accent is NOT used for" rules in 06-UI-SPEC.

**Out of scope (deferred in CONTEXT):** IBM Plex Sans or awesomer's fonts, a Catppuccin Latte light mode, a theme toggle.

### Force-dark approach

The choice: **keep next-themes, forced to dark, plus a static `dark` class and a single Mocha `:root`.**

1. **Tokens live in `:root` only.** Colors no longer depend on any class, so first paint, a no-JS visit and the static demo HTML are already Mocha.
2. **`<html className>` gets a static `dark`** in both `src/app/layout.tsx` and `src/app/layout.demo.tsx`, written as `` `dark ${geistSans.variable} ${geistMono.variable} h-full antialiased` ``. Keep `suppressHydrationWarning`. This turns on the components' `dark:` variants in the server-rendered and exported HTML.
3. **`ThemeProvider` keeps its seam for a later Latte toggle (a deferred idea)** and is forced to dark: `attribute="class"`, `forcedTheme="dark"`, `defaultTheme="dark"`, `enableSystem={false}`, `disableTransitionOnChange`. next-themes' inline script then adds `dark` (and never `light`), whatever the OS setting or any stale `localStorage.theme`. Update the doc comment to: `Dark only (Phase 7): Catppuccin Mocha, forced; the OS setting is ignored.`
4. **Sonner gets `theme="dark"` as a constant.** In next-themes 0.4.x, `useTheme().theme` is not overridden by `forcedTheme`, so it could still read `system` and give a light-styled toast on a light OS. The existing `--normal-bg/text/border` style vars keep mapping to popover, popover-foreground and border.
5. Phase 1 D-16 (follow the OS) is retired. There is no toggle and no `prefers-color-scheme` rule anywhere.

This is the least invasive option: one CSS file, one provider prop change, and one class in each of the two layouts. The static export needs no build change.

## Claude's Discretion (decisions taken, open items)

1. **shadcn `--accent` = surface1, not mauve.** In shadcn, `--accent` is the hover and pressed surface used by ghost buttons, toggles and menu focus. Painting it mauve would break the Phase 6 rule that toggles and ghost actions are never accent. The brand accent is `--primary`.
2. **`--muted` = mantle `#181825`.** Wells (spine crops, thumbnail placeholders, code blocks) sit inside surface0 cards. Surface0 would make them invisible. Surface1 would put subtext0 at 4.10, below AA. Mantle reads as a recess (1.40 against the card) and keeps muted text at 7.89. One side effect: on the bare page, `hover:bg-muted` (the header status indicator, default-variant toggle hover) is only a faint darkening (1.07). This is accepted: there is a cursor change and the control has a label.
3. **`--secondary` = surface1**, so secondary badges ("Saved", "Installed", "Added manually", "Already listed") stand off surface0 cards, with text at 6.31.
4. **Two new tokens**, `--primary-hover` (lavender, locked hover) and `--destructive-foreground` (base, for C-1 and C-2), plus the unmapped `--selection`. No other token is added.
5. **No `--info` token.** Today no component needs an info or cyan tone. Every badge maps to success, warning, destructive or muted. Sky `#89dcfe` is kept as `--chart-2`. If a later phase needs an info state, add `--info: #89dcfe` then.
6. **Focus ring stays `ring-ring/50`** (50% mauve) instead of the site's 40% glow. Changing it means editing about 20 component class strings, and 50% is more visible.
7. **Force-dark through next-themes plus a static class** (see Force-dark approach), rather than removing next-themes. This keeps the provider as the seam for the deferred Latte toggle.
8. **Header keeps `/80`** as locked. `/90` is the documented fallback if the bright-photo backstop fails.
