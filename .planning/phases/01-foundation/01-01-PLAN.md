## Phase Goal

**As the** owner cataloguing my discs, **I want to** launch the app locally with one command and set up my credentials, **so that** all state lives in one portable data folder and background work survives restarts and hot reloads.

(Derived word-for-word from the ROADMAP Phase 1 Goal line, which is not in user-story form. Flagged: run `/gsd-mvp-phase 1` to restate it if this framing is wrong.)

**This plan's slice (walking skeleton):** the owner runs `pnpm dev`, opens http://127.0.0.1:3000/settings, clicks **Queue test job**, and watches the header status go from Working to Worker idle while the single background worker runs the job from SQLite.

<objective>
Stand up the whole stack once, thinly and for keeps: scaffold, 127.0.0.1-only launch, Host/Origin guard, boot hook, portable data folder, SQLite + Drizzle with migrations at boot, a durable jobs table with an atomic claim, a globalThis worker singleton, the status/dev routes, and the app shell with a live status indicator.

Purpose: prove the architecture end to end (register-once boot, dual module graphs, globalThis singletons, migrations at boot, no DB access at build time) before Plans 01-02, 01-03 and 01-04 expand it.
Output: a runnable app, the initial migration, `scripts/verify-skeleton.ts`, and SKELETON.md decisions honored.
</objective>
