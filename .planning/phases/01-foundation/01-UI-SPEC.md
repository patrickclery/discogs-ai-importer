# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: `--auto`. No user questions were asked. Values come from 01-CONTEXT.md (D-09, D-10, D-16, D-17), 01-RESEARCH.md (Standard Stack), or are researcher defaults marked `[default]`.

**Surfaces in scope:** the app shell (top nav + worker status indicator), the `/upload` and `/spines` placeholders, the `/settings` page, the root redirect, and the global error and loading states. Nothing else.
**Out of scope:** upload dropzone, spine review list, Discogs candidate picker, OAuth connect, backup UI. The tokens below are chosen so those later phases can reuse them.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-text gap inside badges and buttons, gap between status dot and text |
| sm | 8px | `2` | Gap between buttons in a row, label-to-input gap, nav link gap |
| md | 16px | `4` | Gap between fields inside a card, card header-to-content gap |
| lg | 24px | `6` | Card padding (`p-6`), gap between cards, page horizontal padding |
| xl | 32px | `8` | Page title block to first card, top padding of `<main>` |
| 2xl | 48px | `12` | Empty-state vertical padding |
| 3xl | 64px | `16` | Empty-state top offset from header |

Layout constants:
- Header height is 56px (`h-14`). It is sticky (`sticky top-0 z-40`) with a 1px bottom border.
- The shell container is `max-w-6xl` (1152px), `mx-auto`, `px-6`. It is wide so Phase 2's spine list fits.
- The Settings content column is `max-w-2xl` (672px), left-aligned inside the shell container.
- Interactive controls are 36px tall (`h-9`). Icon buttons are 36x36 (`size-9`).

Exceptions:
- 1px borders (`border`) and the 2px active-nav underline (`h-0.5`) are allowed.
- The status dot is 8px (`size-2`).
- 36px targets are used instead of 44px, because this is a desktop-only local tool. The minimum supported viewport is 360px wide. There is no touch-first layout.

## Typography

Uses Tailwind's default size/line-height pairs, with no overrides.

| Role | Size | Weight | Line Height | Tailwind | Used for |
|------|------|--------|-------------|----------|----------|
| Caption | 12px | 400 | 16px (1.33) | `text-xs` | Badges, status indicator text, field descriptions, tooltip text |
| Body | 14px | 400 | 20px (1.43) | `text-sm` | All body copy, inputs, buttons, labels (labels use 500), nav links, error and result text |
| Heading | 16px | 500 | 24px (1.5) | `text-base font-medium` | Card titles, wordmark, empty-state titles |
| Display | 24px | 500 | 32px (1.33) | `text-2xl font-medium tracking-tight` | Page title (one per page) |

Weights: **400 (regular)** and **500 (medium)** only.
- Several shadcn primitives ship with `font-semibold` (CardTitle, AlertDialogTitle and others). After `shadcn add`, replace `font-semibold` with `font-medium` in `src/components/ui/*`. App code never uses `font-semibold` or `font-bold`.
- Mono (`font-mono`, same sizes) is used only for masked secret values, file paths and numeric job counts (`tabular-nums`).

## Layout & Interaction Contract

### Root `/`
Server-side `redirect('/upload')`. Nothing is rendered.

### App shell (`src/app/layout.tsx`)
- `<header>` (sticky, 56px, `bg-card`, `border-b`), then `<main class="max-w-6xl mx-auto px-6 py-8">`.
- **Header left:** the wordmark is a link to `/upload`. It shows a lucide `Disc3` icon (20px), a 8px gap, and "Discogs AI Importer" (Heading role). Below 640px (`sm`), only the icon shows, with `aria-label="Discogs AI Importer"`.
- **Nav** follows the wordmark after a 24px gap. It is a `<nav aria-label="Main">` with three links in this order: **Upload** (`/upload`), **Spines** (`/spines`), **Settings** (`/settings`). Each link is a ghost-style link, 36px tall, `px-3`, Body size, with an 8px gap between links.
  - Active link (matched by path prefix with `usePathname`): `text-foreground`, `aria-current="page"`, and a 2px accent bar at the bottom edge of the header.
  - Inactive link: `text-muted-foreground`, with `hover:text-foreground` on hover.
  - Labels are text only, with no icons.
- **Header right:** `StatusIndicator`.

### Status indicator (D-17)
- It is a client component. It polls `GET /api/status` every 5000ms using `setTimeout` chaining (not `setInterval`). It fetches immediately on mount, pauses while `document.visibilityState === 'hidden'`, and refetches on `visibilitychange` back to visible.
- Rendered as an inline `<button type="button">` that is a Tooltip trigger, so it is keyboard-focusable. It is 36px tall with `px-3`, an 8px dot, a 4px gap, and Caption text. There is no border or background; on hover it gets `bg-muted`.

| State | Condition | Dot | Text |
|-------|-----------|-----|------|
| Loading | Before the first response | `bg-muted-foreground` | `Checking worker…` |
| Idle | Worker present, queued + running = 0 | `bg-success` | `Worker idle` |
| Busy | Worker present, queued + running ≥ 1 | `bg-success`, with `animate-pulse` (disabled under `motion-reduce`) | `Working · {n} queued` (`n` = queued + running, mono `tabular-nums`) |
| Failed jobs | Any lane has failed > 0 (shown in addition to Idle or Busy) | unchanged | the text above + ` · {f} failed` in `text-destructive` |
| Stopped | Response has no worker | `bg-destructive` | `Worker stopped` |
| Unavailable | Fetch error or non-200 | `bg-muted-foreground` | `Status unavailable` |

- The tooltip content is one line per lane (Caption, mono numbers): `anthropic — {queued} queued, {running} running, {failed} failed`, and the same for `discogs`. In the Unavailable state, the tooltip reads `Couldn't reach /api/status. Retrying every 5 seconds.`
- Below 640px, the text is visually hidden (`sr-only`) and only the dot shows.
- It is NOT an `aria-live` region, so polling never spams screen readers. The button's accessible name is the current text.

### Upload placeholder (`/upload`)
A shadcn `Empty`, centered in the main column, with `pt-16` and `pb-12`.
- Media: lucide `ImageUp` (20px) in the `Empty` icon slot.
- Title (Heading) and description (Body, muted) use the copy below.
- Action: a primary Button "Open Settings" linking to `/settings`. It is shown **only if the Anthropic key is not configured**. When the key is configured, there is no action and the alternate description is used.

### Spines placeholder (`/spines`)
The same `Empty` layout, with the lucide `Rows3` icon and no action.

### Settings (`/settings`)
- Uses `await connection()` (RESEARCH Pitfall 1). It is server-rendered from masked DTOs only.
- Page title block: Display "Settings", then a Body muted description with an 8px gap. There is 32px from this block to the first card.
- The cards are stacked vertically with a 24px gap, in this order:

**1. Card "Anthropic"**
- Description: the copy below.
- `SecretField` for "API key" (env name `ANTHROPIC_API_KEY`).
- `Separator`, then the "Vision model" `Select` with two options: `Claude Opus 5.5 (claude-opus-5-5)`, the default, and `Claude Sonnet 5.5 (claude-sonnet-5-5)`. It saves on change through the `saveSetting` action. The Select is disabled while pending.
- Card footer row (`flex justify-between`): left, the "Test key" outline button with the test result inline to its right; right, nothing.

**2. Card "Discogs app"**
- Description: the copy below, including a link.
- A `SecretField` for "Consumer key" (`DISCOGS_CONSUMER_KEY`), a `Separator`, then a `SecretField` for "Consumer secret" (`DISCOGS_CONSUMER_SECRET`).
- There is no Test button (D-10 / deferred to Phase 3).

**3. Card "Data folder"** (read-only, `StoragePaths`)
- Two rows, each with a Label and a muted well (`bg-muted rounded-md px-3 py-2 font-mono text-xs break-all`):
  - "Data folder" shows the absolute `DATA_DIR`.
  - "Secrets file" shows the absolute `secrets.json` path.
- The description is the copy below. There are no actions.

**4. Card "Developer"** (`DevJobTrigger`)
- Rendered only when the dev trigger route is enabled (`NODE_ENV !== 'production'` or `APP_TEST_HOOKS=1`).
- An outline button "Queue test job" POSTs to `/api/dev/jobs`. It shows a success toast `Test job queued` and on failure shows inline error text.

### SecretField state machine
The field's frame is a `Field`. The label row is `flex justify-between`: the `FieldLabel` is on the left and a source Badge on the right.

| Source | Badge | Value area | Actions |
|--------|-------|-----------|---------|
| unset | `outline` "Not set" | Password Input (empty, placeholder from the copy table) with a 36px ghost icon button inside the right edge toggling show/hide (`Eye` / `EyeOff`, `aria-label` "Show value" / "Hide value"). The toggle only reveals what the user has typed in this session. | Primary "Save key" (Anthropic) or "Save credentials" (Discogs, which saves both fields at once) |
| file | `secondary` "Saved" | Muted mono well showing the mask, e.g. `sk-ant-…a1b2` (`••••` if ≤ 8 chars) | outline "Replace", ghost destructive "Clear" |
| env | `outline` with lucide `Terminal` icon, "From env" | Muted mono well with the env value's mask, and below it a FieldDescription with the env-override copy | outline "Replace", plus ghost destructive "Clear" only if a saved file value also exists |

- **Replace:** swaps the well for an empty password Input. Focus moves to the input. Buttons become primary "Save key" or "Save credentials" plus outline "Cancel". Cancel or Escape restores the well, and focus returns to Replace.
- **Save:** submits through a Server Action. While pending, the button shows a `Spinner` and the label "Saving…", and the input and buttons are disabled. On success: the input is cleared, the page revalidates to show the new mask and badge, and a toast shows the success copy. The action's return state carries only `{ ok, error? }`. It never echoes the value.
- **Validation (zod, server-side, shown inline via `FieldError`):** values are trimmed and must be non-empty with no whitespace. The Anthropic value must start with `sk-ant-`. Errors render in `text-destructive` Body under the input. The input gets `aria-invalid` and `aria-describedby` pointing to the error.
- **Clear:** opens an AlertDialog with the destructive copy. The confirm button uses the `destructive` variant. On success, a toast shows and the field returns to unset (or to the env state if an env value exists).
- **Discogs:** each field has its own badge and state. When both are unset, they share one "Save credentials" button. In the file or env state, each field has its own Replace and Clear. A partially configured state (key set, secret not set) is valid: each badge shows its own state.
- **Never:** a secret in `defaultValue`, `value` from the server, `placeholder` (except the static example prefix), toast text, action state or logs (D-09, Pitfall 8).

### Test key (D-10)
- An outline Button "Test key" with a lucide `PlugZap` icon. It tests the **effective** key (env if set, else file).
- It is disabled when no key is configured. A Tooltip on a wrapping span then shows `Save a key first`.
- Pending: a `Spinner` and "Testing…". The button is disabled.
- The result renders inline next to the button. It is a `role="status"` `aria-live="polite"` region with Body text and a 16px icon: `CircleCheck` in `text-success` for success, `CircleX` in `text-destructive` for failure. The result persists until the next test or until the key changes.

### Loading and errors
- `src/app/settings/loading.tsx`: a title Skeleton (`h-8 w-40`), then three card Skeletons (`h-40 w-full rounded-xl`) with a 24px gap.
- `src/app/error.tsx` (client): centered `Empty` with the lucide `TriangleAlert` icon, the error copy and a primary "Try again" button calling `reset()`. Accent here is allowed as the page's single primary action.
- Save, Clear and Test failures are **inline and persistent** (an `Alert variant="destructive"` at the top of the affected card for I/O errors, or a `FieldError` for validation). Toasts are used for success only.

### Focus and keyboard
- Every interactive element shows the shadcn `focus-visible:ring-[3px] ring-ring/50` ring.
- Tab order: wordmark, nav links, status indicator, then page content.
- The AlertDialog traps focus and returns it to the Clear trigger on close.
- Enter in a secret input submits that field's form.

### Motion
Motion is limited to shadcn defaults (dialog and tooltip fade/zoom, Sonner slide) and the status-dot pulse. Everything respects `motion-reduce`.
