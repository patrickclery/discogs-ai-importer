## Phase Goal

**As the** owner cataloguing my discs, **I want to** launch the app locally with one command and set up my credentials, **so that** all state lives in one portable data folder and background work survives restarts and hot reloads.

**This plan's slice (walking skeleton, completes the click path):** the owner opens http://127.0.0.1:3000/settings, clicks **Queue test job**, and watches the header status go from Working to Worker idle while the worker from Plan 01-01 runs the job. Around it sits the app shell: wordmark, Upload / Spines / Settings nav, the empty states and the error page, in light or dark following the OS.

<objective>
Put the UI layer on the tracer path Plan 01-01 proved over HTTP: shadcn/ui with the UI-SPEC tokens, the sticky header with the live status indicator, the routed pages, and the dev-only Queue test job card.

Purpose: Plans 01-03 and 01-04 add their settings cards and the Upload readiness gate onto this shell; the status indicator is how the owner sees background work for the rest of the project.
Output: the shadcn primitives, ThemeProvider, AppHeader, NavLink, StatusIndicator, DevJobTrigger, the /, /upload, /spines, /settings and error pages, and UI assertions in scripts/verify-skeleton.ts.
</objective>
