## Phase Goal

**As the** owner cataloguing my discs, **I want to** launch the app locally with one command and set up my credentials, **so that** all state lives in one portable data folder and background work survives restarts and hot reloads.

**This plan's slice:** the settings page tells the owner whether the Claude Code CLI is installed and logged in to their subscription, lets them pick the vision model and test it, and the Upload page reflects whether vision is ready. No API key is involved (D-18).

<objective>
Replace the API-key half of FOUND-03 with the D-18 Claude CLI setup: detect the CLI and its login, warn about ANTHROPIC_API_KEY, persist the vision model in the settings table, run a headless test through the subscription, and ship the child-process runner (timeout, abort, process-group kill, scrubbed env) that Phase 2's vision job will call from the worker.

Purpose: Phase 2 sends every shelf photo through `claude -p`; it must use the owner's plan, never API billing, and a hung CLI must not hold a worker lane.
Output: src/server/proc/run.ts, src/server/claude/cli.ts, src/server/settings.ts, Claude CLI card, ModelSelect, Test Claude button, Upload readiness, fake CLI fixture, scripts/verify-claude-cli.ts.
