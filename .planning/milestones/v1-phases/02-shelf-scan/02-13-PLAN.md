## Phase Goal

**As the** owner cataloguing my CDs, **I want to** drop shelf photos and see every detected spine as a horizontal crop next to the AI-extracted fields, which I can correct, **so that** misreads are easy to see and fix and each photo costs exactly one Claude call.

(Derived from the ROADMAP Phase 2 Goal line and the PROJECT core value; flagged in Plan 02-01.)

**This plan's slice (gap G-02-3):** when the app restarts while /upload or /spines is open and every photo is Done, the "Couldn't refresh" alert goes away by itself a few seconds after the server is back, as its copy promises.

<objective>
Close UAT gap G-02-3: make the photos/spines refetch interval error-aware so a failed poll keeps retrying even when no photo is active, and correct the UI-SPEC rule that caused it.

Root cause (binding, from .planning/debug/couldnt-refresh-alert-never-clears.md): photosRefetchInterval decides polling from the last data only and ignores the query's error state. With every photo Done it returns false, so after a failed refetch (for example the refetchOnWindowFocus fetch while the server is down) nothing schedules another fetch while the tab stays focused, and isError never resets. 02-UI-SPEC.md:183 mandates false when idle while :358 promises "retrying every few seconds".

Purpose: D-12 polled status must recover on its own; the alert must not lie.
Output: error-aware photosRefetchInterval with POLL_RETRY_MS, both call sites wired, a QueryObserver regression test, unit tests, and the corrected UI-SPEC line.
</objective>
