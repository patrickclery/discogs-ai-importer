## Phase Goal

**As the** owner cataloguing my CDs, **I want to** drop shelf photos and see every detected spine as a horizontal crop next to the AI-extracted fields, which I can correct, **so that** misreads are easy to see and fix and each photo costs exactly one Claude call.

(Derived from the ROADMAP Phase 2 Goal line and the PROJECT core value; flagged in Plan 02-01.)

**This plan's slice:** a photo POSTed to `/api/photos` is stored once by its hash, gets exactly one queued scan run that can never be retried into a second call, and shows up as Queued in the photo list; an identical re-upload costs nothing. Plan 02-04 adds the scan job that runs the queued photo; Plans 02-06 and 02-07 build the upload page on this route.

Create the Phase 2 data model and the ingest path: upload route, magic-byte detection, content-addressed storage, dedup, run + job in one transaction, and the photo list.

Purpose: INGEST-01 and INGEST-03 on the server; D-13 spine identity and D-10 field storage land in the schema now so every later plan builds on them.
Output: the Phase 2 migration, ingest module, upload and list route, DTO contracts, and scripts/verify-scan.ts.
</objective>
