## Phase Goal

**As the** owner cataloguing my CDs, **I want to** drop shelf photos and see every detected spine as a horizontal crop next to the AI-extracted fields, which I can correct, **so that** misreads are easy to see and fix and each photo costs exactly one Claude call.

(Derived from the ROADMAP Phase 2 Goal line and the PROJECT core value; flagged in Plan 02-01.)

**This plan's slice (gap G-02-5):** Escape on a spine field always throws the draft away, and a later click-away always saves, whatever else in the browser touches focus first.

<objective>
Close UAT gap G-02-5: make SpineField's Escape cancel independent of whether blur or keydown arrives first, and remove the persistent skip flag that silently drops a later save.

Root cause (binding, from .planning/debug/escape-saves-draft-on-first-edit.md): the Escape cancel assumes the input is still focused when onKeyDown runs. If focus leaves first (for example a browser extension's window-capture Escape handler blurs the active element), onBlur commits the draft before the reset, then onKeyDown arms the skip-next-blur flag with a blur() that is a no-op. The stale flag swallows the next blur, so a later click-away save is silently dropped (the field shows the new text, the server keeps the old value).

Purpose: D-08 autosave on blur must be trustworthy; REV-02 edits must never be lost or saved against the owner's intent.
Output: a pure createFieldCommit controller with ordering tests, wired into SpineField with an unmount flush.
</objective>
