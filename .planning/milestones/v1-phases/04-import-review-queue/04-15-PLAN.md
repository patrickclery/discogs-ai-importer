## Gap

**Source:** 04-UAT.md gap G-04-7 (test 7, severity major), diagnosed in .planning/debug/long-photo-name-overflow.md. UAT test 3 is a deferred follow-up (Undo import, D-02 / DATA-01) and is NOT planned here.

**Root cause (confirmed by a headless repro with the real compiled CSS):**

1. **Dialog.** The title in duplicate-import-dialog.tsx carries two overflow-wrap utilities. Tailwind 4.3 emits the break-words rule later, so `overflow-wrap: break-word` wins. That value does not lower min-content, so the 123-char unspaced name sets the title's min-content (~1131px). It propagates through AlertDialogHeader (a grid item with min-width:auto) into the single implicit `auto` column of AlertDialogContent's grid. The box stays 512px, but the column, and with it the body, the picture row and the footer buttons, is 1131px wide.
2. **Dropdown.** SelectItem's `*:[span]:last:flex` makes the ItemText span a flex container with min-width:auto, so the inner `truncate` span never shrinks (no ellipsis), and SelectContent's overflow-x-hidden hard-clips it. Nothing carries a `title` for hover.

**Fix shape (local className only, per the orchestrator's scope):** both shared primitives (src/components/ui/alert-dialog.tsx, src/components/ui/select.tsx) already pass `className` through `cn`, so every fix is applied at the call site. The primitives are not edited. A planning probe confirmed that `cn` keeps every new token next to the primitives' base classes, that both component modules import cleanly in Vitest's node environment, and that `react-dom/server` renderToStaticMarkup works there.

**Out of scope, deliberately untouched:** src/components/already-in-collection.tsx:106 has the same pair of overflow-wrap utilities, but UAT test 6 passed: its `min-w-0` flex column contains it. The Settings folder Select passed UAT test 4. Do not edit either.
