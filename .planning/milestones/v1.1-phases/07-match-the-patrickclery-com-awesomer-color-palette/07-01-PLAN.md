Planner findings the executor must know (verified against the tree and the last demo export on 2026-10-25):
- The demo root page (`src/app/page.demo.tsx`) is a client redirect to /upload. In the export, `out/index.html` is Next's redirect shell, `<html id="__next_error__">` with no layout class and no stylesheet. The UI-SPEC's demo assertion names `out/index.html`, which would fail every build. Rule i therefore checks the layout-rendered pages instead: every demo page route except the root, plus `404.html` (upload, spines, settings and 404 all render `<html lang="en" class="…">` today). The failure text keeps the UI-SPEC wording as its prefix.
- Because that redirect shell has no stylesheet, a light-mode browser would flash a white canvas for a moment on the demo root. Both layouts therefore also export a `viewport` with `colorScheme: 'dark'`. Next writes this as a color-scheme meta tag in every page head, including the shell, so the browser canvas starts dark. This is the force-dark approach applied to the one page the class cannot reach (Claude's Discretion: force-dark mechanism).
- build-demo.ts rsyncs the working tree (tracked plus untracked files) into a scratch copy, so uncommitted edits are built. It prints `DEMO_OUT=<dir>`. Lightning CSS keeps hex custom-property values verbatim (for example `--primary:#4f46e5;` in today's build), so the exported CSS can be grepped for token values.
- Vitest runs only `src/**/*.test.ts` in a node environment (no DOM). Tests read files with node:fs and render with `renderToStaticMarkup`.
